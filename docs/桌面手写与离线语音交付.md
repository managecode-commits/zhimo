# 桌面手写与离线语音：实现与验收边界

本次完成基础单字手写／短句语音的跨端接入，不代表前次评估中的全部 P2 能力已完成。

## 使用

选择 Zhimo 并将光标放入普通输入框：Ctrl+Shift+H 打开手写，Ctrl+Shift+F10 打开语音。
Windows 可右击中／英模式图标进入菜单；Linux 可使用 IBus 属性菜单或 Fcitx5 状态区动作。
Ctrl+Shift+V 不被语音功能占用。若应用本身使用上述快捷键，可改用鼠标入口。

手写一次一字，支持撤笔、清空、停笔识别、候选滚动与点击上屏，最多展示 100 项。
语音点击开始才访问默认麦克风，最长 60 秒；停止后离线转录，预览后确认上屏。
取消、超时、进程失败、损坏／超长结果均不提交；不写剪贴板、不模拟按键、不保存原始笔迹或录音。
语音模型使用内置 Whisper base Q5_1 与 Silero VAD，并在加载前验证 SHA-256。

## 进程与安全

Windows 使用独立原生 Win32 面板，只有指定的匿名管道句柄可继承；Job Object 负责取消时清理子进程。
TSF 使用正常编辑会话上屏，并再次检查上下文、请求代次、选区和敏感输入范围。
Linux 两个适配器共用 GTK 面板进程，匿名 stdout 管道返回一次确认文本；不建立开放 TCP 服务。
父进程验证退出状态、UTF-8、16 KiB 上限、焦点与敏感范围，并在取消时终止整个子进程组。
识别均不在宿主输入事件线程执行。独立面板无心跳持久化，最长 5 分钟退出。

Linux 使用 PulseAudio 客户端 `parec`，适用于 PulseAudio 或启用了兼容服务的 PipeWire 会话。
Windows 首版使用 WinMM 默认录音设备，尚未实现 WASAPI、录音设备选择、硬件格式回退。

## 构建

本次本机构建产物：

- Windows x64：`target/packages/zhimo-windows-desktop-input-r2-20260915.zip`。
- Ubuntu 24.04 amd64：`target/zhimo-ubuntu2404.MThHK3/packages-desktop-r3/`。
- Debian 12 amd64：`target/zhimo-debian12.HC6Ht7/packages-desktop-r3/`。

Linux 安装该目录中的 `zhimo-core` 和所选 `zhimo-ibus`／`fcitx5-zhimo`，不要混装不同发行版包。
首轮 `packages-desktop-input`、`packages-desktop-r2` 是保留的中间产物，请使用上述最终路径。

先运行 `bash tools/prepare-offline-speech.sh` 准备锁定的源码、模型和许可文件。
Linux 继续使用 `bash tools/build-linux-deb.sh ubuntu2404` 或 `debian12`，会构建语音共享库，
将面板、绘图依赖、录音工具依赖、模型及许可一起纳入 DEB。

Windows 使用匹配工具链先构建 `platform/shared-speech`；再配置 Windows TSF：

```text
-DZHIMO_BUILD_DESKTOP_PANEL=ON
-DZHIMO_SPEECH_LIBRARY=<Windows 语音导入库完整路径>
```

MinGW 打包时在原 `tools/package-windows-test.py` 参数上增加：

```text
--speech-runtime target/shared-speech-windows/libzhimo_speech.dll
```

不启用完整包参数时不会自动把语音模型塞入普通 TSF 包；不能用普通包验收新面板。
原有安装包不会自动改变。Windows 使用 `install.ps1 -Upgrade`；Linux 安装同目录的 core 与所选插件。
完成后注销重新登录，保留原用户词库。

## 验证与尚未完成

- Linux：按键回归、子进程 IPC 拒收／取消测试、Xvfb 绘图与预览确认测试、语音边界测试、DEB 安装加载卸载。
- 共享库：公开中英文音频及取消测试仅证明链路，不作为识别字错误率基准。
- Windows：完成交叉编译与 PE 依赖检查；没有 Windows 运行环境，未验证真实录音、菜单、选区保护及 EmEditor。
- 未验证真实 GNOME/KDE、X11/Wayland、输入法客户端切换；Wayland 若不支持所需的不抢焦点行为，可能取消面板而非完成输入。
- 尚未迁移 Android 字形融合／连写分字／个性化纠错学习；桌面仍使用现有单字轨迹模型。
- 尚未实现实时增量语音、预览内编辑、设备选择、简繁归一化及桌面准确率／延迟基准。
- 不保证所有应用报告敏感范围；自定义控件必须继续专项验收。

这些缺项不能以“全部完成”标记。下一阶段应先在目标桌面实测基础闭环，再迁移融合识别与连写，
并以同一批真实笔迹和录音比较各端准确率，避免只增加候选而掩盖识别质量问题。
