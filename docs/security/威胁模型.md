# 威胁模型与安全边界

## 保护对象

- 用户正在输入的正文、周边文本和候选反馈。
- 个人词库、学习计数、转录文本、保存的录音。
- 同步主密钥、包签名私钥、设备与账户凭据。
- 输入法在安全文本框中的隔离承诺。

## 信任边界

平台 IME 壳可看到当前输入会话；通用 Runtime 只接收规范化事件；语言引擎无窗口、麦克风和网络权限；语音 worker 不直接提交文本；同步服务只接收客户端加密 envelope；语言包只有通过可信 Ed25519 公钥验证后才可进入资源目录。

## 已实现控制

- 密码 scope 禁用学习和语音启动。
- SQLite FULL 同步事务、逻辑时钟与删除墓碑。
- XChaCha20-Poly1305 随机 nonce 和认证加密；服务端不持有密钥。
- Bearer token 只保存 SHA-256 摘要并恒定时间比较。
- Ed25519 签名覆盖 manifest 与按名称排序的所有资源；拒绝绝对路径和 `..`。
- C ABI 只暴露不透明句柄和宿主管理的 UTF-8 生命周期。
- 原始音频仅写入随机会话临时 WAV，worker 完成后删除；取消/崩溃残留由平台启动清理负责。
- CI 用锁定版本的 `cargo-audit` 检查 `Cargo.lock` 与 RustSec 公开安全通告。
- Android Release keystore 和口令不进入仓库；只通过本地机密管理器或 CI secret 注入，产物必须再经 `apksigner` 验证证书。

## 发布前必须补齐

- 主密钥必须由各平台安全硬件/凭据库生成和封装，禁止硬编码或通过命令行传递。
- 同步服务必须使用 TLS、正式账户令牌、限流、审计、备份与租户隔离。
- 模型与语言包发布流水线必须保护离线签名私钥，生成 SBOM 和许可证报告。
- 对 FFI、包解析、同步乱序和音频文件做 fuzz；对日志做正文泄漏扫描。
- 在所有目标系统验证安全输入、剪贴板、崩溃转储、应用切换和扩展容器边界。
