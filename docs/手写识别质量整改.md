# 手写识别质量整改

> 后续已新增实验性离线字形模型和“前五＋更多网格”界面，替代本页记录的候选翻页方式。最新 APK、启用方式和验收边界见 [字形模型与网格界面](手写字形模型与网格界面.md)。

日期：2026-09-13。针对“很多字连候选中也没有”的反馈，本轮修复输入归一化和 Android 候选可达性。**不是模型替换，也不代表真实手写质量已全部达标。**

## 已实现

- 公共 Rust 生产识别接口在校验原始笔迹后，计算整个字的包围框，居中并等比例映射到 1000 × 1000 方形、四周保留 10% 边距。横笔/竖笔/单点不做零除，不逐笔归一化，不擅自重排笔顺。
- Android 与其他 C ABI 调用者使用同一归一化入口。底层 `Model::recognize` 保留原始 Zinnia 特征路径用于算法回归；生产入口为 `recognize_normalized`。原版 C++ 候选完全一致不再是生产预处理的验收条件。
- C ABI 最多返回 100 候选，Android 会话同步保留 100 个；每页 10 个，有上一页/下一页、页数和横滑提示。翻页后回到横向列表起点，补笔/清空/编辑器切换后旧结果与旧按钮失效。
- 新增 Rust 平移、等比例缩放、不同画布尺寸下前 100 候选一致性、单点和非法画布回归；Android 面板测试覆盖第 100 个候选提交、页边界和旧按钮不得重复提交。
- 模型仍内置、校验后加载，不下载新模型、不增加联网权限，不上传或持久化真实用户笔迹。

`tools/verify-handwriting-robustness.py` 对固定 23 个模型源数据字符执行六种确定性变换，共 138 个样例。数据并非真实用户独立测试集；笔顺逆序属于压力测试，不代表常见笔顺差异的实际分布。

## 模型结论与未完成验收

当前 6,763 类 Zinnia 模型仍可作为规范笔顺的离线单字基础，但不能视为随手写、连笔场景的成熟方案。本轮没有用另一个未经验证的模型冒充升级。更换模型的准入条件是：明确的权重/字表再分发许可、离线 Android 推理、覆盖字表、真实多人独立测试集、Top1/Top5/Top20 指标、不同笔顺/连笔/低端设备延迟和内存评测。需要针对这批失败样例验证，不能仅对源训练样例调参。

用户失败笔迹尚未提供，因此无法确认本轮是否解决其具体写法；未采集、上传或保存用户笔迹。连续词句和重叠书写仍未实现。Linux GTK 本轮仅通过公共 ABI 获得归一化；其界面仍显示前五个候选，未扩展桌面翻页。
