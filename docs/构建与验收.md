# 全平台构建、安装与验收手册

本文是仓库内所有可执行程序和平台 App 的统一构建入口。命令默认从仓库根目录执行。

## 1. 产物状态总览

| 目标 | 当前工程形态 | 构建主机 | 构建入口 | 安装/运行状态 |
|---|---|---|---|---|
| Android | Gradle `InputMethodService` App | Linux/macOS/Windows | `tools/verify-android-beta.sh` | 可生成 APK 并安装 |
| Linux IBus | Python IBus 适配器 + Rust `.so` | Linux | `platform/linux-ibus/install-user.sh` | 可按用户安装 |
| Linux Fcitx5 | C++20 插件 + Rust `.so` | Linux | Cargo + CMake | 可按用户安装 |
| Windows | TSF COM DLL | Windows 10/11 | Cargo + CMake/MSVC | 可注册为输入法 |
| macOS | InputMethodKit target 源码 | macOS | Cargo + Xcode | 尚无 `.xcodeproj`，需先创建 target |
| iOS/iPadOS | 容器 App、键盘扩展 target 源码 | macOS | `tools/build-apple-core.sh` + Xcode | 尚无 `.xcodeproj`，需先创建 targets |
| CLI 工具 | Rust binaries | Rust 支持的平台 | Cargo | 可直接运行/安装 |
| 同步服务 | Rust HTTP service | Rust 支持的平台 | Cargo | 可直接运行/部署 |

Android、Windows、Linux 产物不能跨系统互换。Windows TSF 应在 Windows/MSVC 上构建，
Apple App 必须在 macOS/Xcode 上构建和签名。

## 2. 通用 Rust 环境

仓库由 `rust-toolchain.toml` 固定 Rust 1.98.0。安装 rustup 后，在根目录确认：

```bash
rustup show
cargo --version
```

构建全部 Rust crate 和命令行程序：

```bash
cargo build --workspace --release
```

完整源码门禁：

```bash
./tools/verify.sh
```

它会执行格式检查、全 workspace Clippy（warning 即失败）、常规测试、C ABI 动态链接
测试和 C++ 平台边界测试。依赖漏洞门禁为：

```bash
cargo install cargo-audit --locked --version 0.22.2
cargo audit
```

## 3. Android 输入法 App

### 3.1 环境

- JDK 17
- Android SDK Platform 37.0
- Android Build Tools（包含 `apksigner`）
- Android NDK 28.2.13676358
- `cargo-ndk` 4.1.2
- 三个 Rust Android targets

```bash
rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
cargo install cargo-ndk --locked --version 4.1.2
```

接受 Android 许可证并安装 SDK/NDK 是开发者本机操作。构建脚本只检查已有许可证记录，
不会自动接受许可证。若自动发现失败，显式设置：

```bash
export JAVA_HOME=/path/to/jdk-17
export ANDROID_HOME=/path/to/android-sdk
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/28.2.13676358"
```

### 3.2 Debug APK

统一构建和验证入口：

```bash
./tools/verify-android-beta.sh
```

脚本会依次：

1. 为 `arm64-v8a`、`armeabi-v7a`、`x86_64` 编译 Rust Runtime；
2. 执行 Android Lint；
3. 构建 Debug APK 和 AndroidTest APK；
4. 检查签名、ABI、ELF 架构和动态依赖；
5. 检测到已授权设备时自动安装并运行六项 instrumentation 测试。

产物：

```text
platform/android-ime/app/build/outputs/apk/debug/app-debug.apk
```

手工安装、启用和选择：

```bash
adb install -r platform/android-ime/app/build/outputs/apk/debug/app-debug.apk
adb shell ime enable dev.shurufa.ime/.ShurufaInputMethodService
adb shell ime set dev.shurufa.ime/.ShurufaInputMethodService
```

仅重新构建 Gradle 层时，必须先确保 `app/src/main/jniLibs/<abi>/libime_ffi.so` 已生成：

```bash
./tools/build-android-core.sh
cd platform/android-ime
./gradlew :app:assembleDebug
```

### 3.3 签名 Release APK

签名机密只能通过本机机密管理器或 CI secret 注入，不能提交到仓库：

```bash
export SHURUFA_ANDROID_KEYSTORE=/absolute/path/release.jks
export SHURUFA_ANDROID_KEY_ALIAS=release
export SHURUFA_ANDROID_STORE_PASSWORD='...'
export SHURUFA_ANDROID_KEY_PASSWORD='...'
export SHURUFA_ANDROID_CERT_SHA256='expected-certificate-sha256'
./tools/verify-android-release.sh
```

产物：

```text
platform/android-ime/app/build/outputs/apk/release/app-release.apk
platform/android-ime/app/build/outputs/apk/release/app-release.apk.sha256
```

默认构建使用内置参考拼音。生产 librime 构建还需令 `ANDROID_RIME_ROOT` 指向分别包含
`arm64-v8a`、`armeabi-v7a`、`x86_64` 前缀的目录；详见
[Android 工程说明](../platform/android-ime/README.md)。

需要完整 Rime 引擎时，推荐使用一条命令完成三个 ABI 的 `librime.so` 获取、交叉编译、
ELF 校验、APK 打包和设备测试：

```bash
./tools/verify-android-rime-beta.sh
```

该入口不要求系统级安装 CMake、Ninja、GHC 或 Cabal，直接复用 Android SDK 中的工具，
并使用锁定提交的官方 librime 源码与 fcitx5-android 静态依赖。默认前缀位于
`target/android-rime`；只生成前缀可执行 `./tools/build-android-librime.sh`，然后令其他
Debug 或 Release 构建的 `ANDROID_RIME_ROOT` 指向该目录。
独立 Rime APK 输出为
`platform/android-ime/app/build/outputs/apk/debug/app-debug-rime.apk`，并生成对应的
`.sha256` 文件。连接设备时，Rime 专用门禁会强制验证原生引擎初始化和选中成功，不允许
以参考拼音回退冒充通过。

仓库已经固定并打包官方 `rime-pinyin-simp` 的 65,125 条词典记录，26键 Rime 和9键
回退共享该词汇来源。需要重建/升级词典时运行：

```bash
./tools/update-rime-pinyin-simp.sh
```

脚本会验证锁定提交的 SHA-256，并同步生成 Android Rime YAML、完整上游许可文本和通用
回退引擎 TSV；不要手工只更新其中一份。

## 4. Linux 桌面输入法

同一个桌面会话只选择 IBus 或 Fcitx5 作为主要框架。Ubuntu/GNOME 默认优先使用 IBus。

### 4.1 IBus（Ubuntu/GNOME 推荐）

Ubuntu/Debian 依赖：

```bash
sudo apt update
sudo apt install -y build-essential ibus python3-gi gir1.2-ibus-1.0
```

编译并按当前用户安装：

```bash
./platform/linux-ibus/install-user.sh
ibus list-engine | grep -A1 -B1 shurufa
ibus engine shurufa
```

脚本将 Release Runtime 和适配器安装到：

```text
${XDG_DATA_HOME:-$HOME/.local/share}/shurufa
${XDG_DATA_HOME:-$HOME/.local/share}/ibus/component/shurufa.xml
```

也可在“设置 → 键盘 → 输入源”中添加 `Shurufa Pinyin`。列表未刷新时重启 IBus，
必要时注销并重新登录：

```bash
ibus restart
```

开发模式（不安装）：

```bash
cargo build -p ime-ffi
SHURUFA_IME_LIBRARY="$PWD/target/debug/libime_ffi.so" \
SHURUFA_USER_DATA_DIR=/tmp/shurufa-ibus-dev \
  python3 platform/linux-ibus/shurufa_ibus.py
```

验证和卸载：

```bash
python3 -m py_compile platform/linux-ibus/shurufa_ibus.py
python3 platform/linux-ibus/runtime_smoke.py
./platform/linux-ibus/uninstall-user.sh
```

卸载脚本会将文件改名为 `.disabled`，以便人工恢复。

### 4.2 Fcitx5

Ubuntu/Debian 依赖：

```bash
sudo apt update
sudo apt install -y build-essential cmake ninja-build \
  fcitx5 fcitx5-config-qt libfcitx5core-dev
```

Release 构建并按当前用户安装：

```bash
cargo build --release -p ime-ffi
cmake -S platform/linux-fcitx5 -B target/fcitx5 -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DSHURUFA_IME_LIBRARY="$PWD/target/release/libime_ffi.so" \
  -DCMAKE_INSTALL_PREFIX="$HOME/.local"
cmake --build target/fcitx5
cmake --install target/fcitx5
fcitx5 -r
```

Ubuntu 可用 `im-config -n fcitx5` 选择框架，注销重登后运行 `fcitx5-configtool`，添加
`Shurufa Pinyin`。诊断：

```bash
fcitx5-diagnose
ldd "$HOME/.local/lib/fcitx5/libshurufa.so"
```

如需卸载，先检查 CMake 安装清单，再删除清单中属于本插件的文件：

```bash
cat target/fcitx5/install_manifest.txt
```

不要盲目递归删除 `$HOME/.local`。

## 5. Windows TSF 输入法

### 5.1 环境

在 Windows 10/11 安装：

- Visual Studio 2022 的“使用 C++ 的桌面开发”工作负载；
- Windows 10/11 SDK；
- CMake；
- Rust 的 `x86_64-pc-windows-msvc` 工具链。

在 **Developer PowerShell for VS 2022** 中执行：

```powershell
rustup target add x86_64-pc-windows-msvc
rustc --version
cmake --version
cl
```

### 5.2 Debug 构建、探针与安装

```powershell
cd C:\path\to\shurufa
cargo build -p ime-ffi
cmake -S platform/windows-tsf -B build/windows-tsf -A x64
cmake --build build/windows-tsf --config Debug
```

主要产物：

```text
build\windows-tsf\Debug\ShurufaTsf.dll
build\windows-tsf\Debug\ime_ffi.dll
build\windows-tsf\Debug\shurufa-tsf-probe.exe
```

先运行边界探针：

```powershell
$env:PATH = "$PWD\build\windows-tsf\Debug;$env:PATH"
.\build\windows-tsf\Debug\shurufa-tsf-probe.exe
```

看到 `TSF core boundary probe passed` 后，只注册 TSF DLL，不要注册 `ime_ffi.dll`：

```powershell
regsvr32.exe "$PWD\build\windows-tsf\Debug\ShurufaTsf.dll"
Stop-Process -Name ctfmon -Force -ErrorAction SilentlyContinue
Start-Process "$env:WINDIR\System32\ctfmon.exe"
```

随后在“设置 → 时间和语言 → 语言和区域 → 中文（简体，中国）→ 语言选项 → 键盘”中
选择 Shurufa，使用 `Win+Space` 切换。若没有出现，注销并重新登录。

### 5.3 Release 构建

```powershell
cd C:\path\to\shurufa
cargo build --release -p ime-ffi
$repo = (Get-Location).Path
cmake -S platform/windows-tsf -B build/windows-tsf-release -A x64 `
  -DSHURUFA_IME_LIBRARY="$repo\target\release\ime_ffi.dll.lib" `
  -DSHURUFA_IME_RUNTIME_DLL="$repo\target\release\ime_ffi.dll"
cmake --build build/windows-tsf-release --config Release
```

卸载前保留 DLL 原路径并执行：

```powershell
regsvr32.exe /u "$PWD\build\windows-tsf\Debug\ShurufaTsf.dll"
```

正式分发还必须完成 Authenticode 签名、安装器和 x64/ARM64 目标矩阵验收；Debug 注册
不等于可发布安装包。

## 6. Apple 平台

当前仓库没有提交 `.xcodeproj`/`.xcworkspace`，所以 Apple 目录是可接入的 target 源码，
不是可直接执行 `xcodebuild` 的完整 App 工程。下列步骤必须在 macOS 和 Xcode 中完成。

### 6.1 iOS/iPadOS 核心 XCFramework

安装 Xcode Command Line Tools 并确认：

```bash
xcode-select -p
xcodebuild -version
./tools/build-apple-core.sh
```

脚本构建 iPhoneOS arm64 与 Simulator arm64/x86_64 静态库并生成：

```text
target/apple-xcframework/ShurufaCore.xcframework
```

### 6.2 iOS 容器 App 与 Keyboard Extension

在 Xcode 创建一个 iOS App 工程和 Custom Keyboard Extension target，然后：

1. 将 `target/apple-xcframework/ShurufaCore.xcframework` 同时加入需要 Runtime 的 target；
2. 将 `platform/apple/ShurufaCore` 加入 `SWIFT_INCLUDE_PATHS`，让 Swift 能按仓库提供的
   `module.modulemap` 执行 `import ShurufaCore`；
3. 将 `platform/apple/ShurufaSession.swift` 加入键盘 target；
4. 将 `platform/ios-keyboard/KeyboardViewController.swift` 加入键盘 target；
5. 将 `platform/ios-container/TranscriptionViewController.swift` 加入容器 App target；
6. 键盘 target 的 Principal Class 指向 `KeyboardViewController`，并配置 App Group；
7. 容器 App 的 `Info.plist` 添加 `NSSpeechRecognitionUsageDescription` 和
   `NSMicrophoneUsageDescription`；键盘扩展不申请麦克风权限；
8. 设置开发团队、Bundle ID 和 provisioning profile 后选择真机或模拟器 Build/Run。

命令行构建需使用实际创建的 scheme 名：

```bash
xcodebuild -project Shurufa.xcodeproj \
  -scheme Shurufa \
  -configuration Debug \
  -sdk iphonesimulator \
  -destination 'platform=iOS Simulator,name=iPhone 16' \
  build
```

真机安装必须使用有效 Apple 签名。第三方键盘启用路径为“设置 → 通用 → 键盘 → 键盘 →
添加新键盘”。iOS 第三方键盘不能直接使用麦克风，语音转录位于容器 App。

### 6.3 macOS InputMethodKit

先为当前 Mac 架构构建 Runtime：

```bash
cargo build --release -p ime-ffi
```

若要生成同时支持 Apple Silicon 和 Intel 的静态库：

```bash
rustup target add aarch64-apple-darwin x86_64-apple-darwin
cargo build --release -p ime-ffi --target aarch64-apple-darwin
cargo build --release -p ime-ffi --target x86_64-apple-darwin
mkdir -p target/apple-macos
lipo -create \
  target/aarch64-apple-darwin/release/libime_ffi.a \
  target/x86_64-apple-darwin/release/libime_ffi.a \
  -output target/apple-macos/libime_ffi.a
```

在 Xcode 创建 macOS App target，链接 Cocoa、InputMethodKit 和 `libime_ffi.a`，将
`platform/apple/ShurufaCore` 加入 `SWIFT_INCLUDE_PATHS`，并加入：

```text
platform/macos-inputmethod/main.swift
platform/macos-inputmethod/InputController.swift
platform/apple/ShurufaSession.swift
include/shurufa_ime.h（通过 ShurufaCore module）
```

配置 `InputMethodConnectionName`、输入法组件声明、Bundle ID 和签名后 Build。将构建出的
`.app` 复制到当前用户目录并重新登录：

```bash
mkdir -p "$HOME/Library/Input Methods"
cp -R /path/to/Shurufa.app "$HOME/Library/Input Methods/"
```

然后在“系统设置 → 键盘 → 文本输入 → 编辑 → 添加输入法”中启用。正式发布仍需 Developer ID
签名、公证以及 Intel/Apple Silicon 应用兼容测试。

## 7. 命令行 App

一次构建四个 CLI：

```bash
cargo build --release \
  -p ime-cli -p transcribe-cli -p data-cli -p ime-bench
```

产物位于 `target/release/`。也可安装到 Cargo bin 目录：

```bash
cargo install --path apps/ime-cli
cargo install --path apps/transcribe-cli
cargo install --path apps/data-cli
cargo install --path apps/ime-bench
```

运行示例：

```bash
cargo run -p ime-cli -- hello
cargo run -p ime-cli -- pinyin nihao
cargo run -p ime-bench --release -- 20000
cargo run -p data-cli -- list /path/to/user.sqlite3
cargo run -p transcribe-cli -- /path/to/whisper-cli /path/to/model.bin /path/to/audio.wav en
```

`transcribe-cli` 当前只读取 PCM16 WAV；模型和音频必须拥有合法使用权。

## 8. 密文同步服务

构建：

```bash
cargo build --release -p sync-server
```

本地运行：

```bash
SHURUFA_SYNC_ACCOUNT=demo \
SHURUFA_SYNC_TOKEN='replace-with-at-least-32-random-characters' \
SHURUFA_SYNC_DATABASE=shurufa-sync.sqlite3 \
SHURUFA_SYNC_BIND=127.0.0.1:8787 \
  ./target/release/sync-server
```

健康检查：

```bash
curl -i http://127.0.0.1:8787/health
```

生产部署必须置于 TLS 反向代理后，并补齐账户签发、限流、审计、备份、数据保留和多租户
隔离；环境变量单账户模式只用于本地闭环与自托管原型。

## 9. 可选生产能力

### 9.1 librime 中文引擎

构建 librime 1.17.0 及依赖，把安装前缀传入：

```bash
RIME_ROOT=/opt/librime \
SHURUFA_RIME_TEST_DATA=/opt/rime-data \
./tools/build-librime-adapter.sh
```

测试必须看到真实中文候选并提交非 ASCII 词典结果。内置参考拼音只用于安装闭环和冒烟，
不代表生产词库质量。

### 9.2 whisper.cpp 离线语音

构建 whisper.cpp 1.9.1，准备有合法使用权的模型与 PCM16 WAV：

```bash
WHISPER_CPP_BIN=/opt/whisper/bin/whisper-cli \
WHISPER_CPP_MODEL=/opt/models/ggml-tiny.en.bin \
WHISPER_CPP_TEST_WAV=/path/to/authorized.wav \
WHISPER_CPP_LANGUAGE=en \
WHISPER_CPP_EXPECTED=country \
./tools/verify-whisper-cpp.sh
```

## 10. 发布验收原则

- Android：APK 构建、签名、ABI 检查通过后，仍需真机覆盖输入连接、横竖屏、后台回收、
  无障碍、耗电、录音权限和 Play 签名。
- Windows：必须在 Notepad、Office、浏览器、终端和 WinUI/UWP 中验证 TSF、候选窗、DPI
  与辅助功能。
- macOS/iOS：没有 Xcode 工程、签名和目标设备报告时，只能标记为“target 源码已实现”。
- Linux：覆盖 X11、Wayland、GTK、Qt、Electron 和终端；IBus/Fcitx5 分开测试。
- 任何缺少目标工具链、签名和真机证据的产物，不能进入“发布完成”口径。

已知外部条件和签名责任参见 [发布阻断与真机验收](发布阻断与真机验收.md)。
