# 内置离线手写交付

> 后续质量修复：生产识别新增整字等比例归一化，Android 扩展到 100 个分页候选。新 APK、修复前后对比及未解决的笔顺限制见 [手写识别质量整改](手写识别质量整改.md)。下文 APK 和算法一致性为上一轮记录。

日期：2026-09-13。执行用户选择的第二种路线：将可再分发的中文手写模型直接随安装资源交付，替换 Android Google ML Kit 下载式手写。

## 能力与边界

Android 安装后进入“手写”，一次写一个简体汉字，停笔后点选候选上屏；支持撤一笔、清空和返回键盘。无需打开 Google 服务、登录或下载模型。模型首次从 APK 解包到应用私有目录，后台初始化，不在主线程识别。损坏缓存从 APK 恢复，不回退到网络下载。

内置 Tegaki/Tomoe 简体中文 0.3 模型含 6,763 个字符类别，原始模型大小 26,834,816 字节。**不是大语言模型，不支持连续词句、重叠字分割、繁体/英文手写，也没有个人字形自训练。** 原 ML Kit 的语言切换和下载入口已移除；英文仍可通过键盘输入。拼音词库及学习能力不由这个手写模型提供。

“离线”仅指这条手写链路；Android 语音识别仍使用系统 Provider，其可用性和联网行为不能由手写模型保证。

## 架构与打包

画板 → 平台会话/版本保护 → 后台 Provider → JNI/C ABI 1.3 → Rust Zinnia 特征提取与分类 → 候选 → 用户点选 → 平台编辑器提交。

- 公共引擎：`crates/ime-handwriting/src/zinnia.rs`，纯 Rust、安全模型解析，不依赖 Google 或生产环境 C++ Zinnia 库。
- C 接口：`ime_handwriting_new`、`ime_handwriting_recognize_json`、`ime_handwriting_free`；能力位 `1 << 6`。句柄由宿主工作线程串行调用，JSON 返回值在下次调用/释放前有效。分数是分类 margin，不是概率。
- 引擎边界：最多 64 笔、每笔 4,096 点、总计 32,768 点；拒绝非有限坐标、非法画布、逆序时间和损坏模型。只接受固定长度和 SHA-256 的模型。
- 平台负责会话隔离、切换输入框/关闭后的旧结果丢弃、密码框策略；C 接口本身不读取编辑器，也不主动上屏。
- Android 不保存原始笔迹、不通过这条链路上传笔迹；已移除 ML Kit 依赖和 App 的 INTERNET 权限。系统语音服务是独立进程，不能据此宣称所有语音离线。
- Android Gradle 自动包含 `models/`，并在 `preBuild` 校验模型哈希、长度和许可证/源文件存在性。模型已纳入仓库资源，不在构建时临时下载。

| 平台 | 本轮接入 | 验证边界 |
|---|---|---|
| Android | 画板、候选、JNI/Rust、内置资源、缓存修复 | 三 ABI 编译；API 35 x86_64 模拟器验收见下文 |
| Linux IBus | GTK 单字画板，Ctrl+Shift+H；安装脚本复制模型 | Python 语法通过；真实桌面焦点、候选点击及 Wayland 行为尚未验收 |
| Linux Fcitx5 | C ABI 可用，CMake 安装模型资源 | 尚无手写画板入口，本轮未构建插件 |
| Windows TSF | C ABI 可用，CMake 复制模型资源到 DLL 同级 models | 尚无手写画板入口，未进行 Windows 构建/安装验收 |
| macOS / iOS | 公共 ABI，XCFramework 构建脚本输出模型资源 | 需把 Resources/handwriting 加入实际使用目标的 Copy Bundle Resources；没有手写 UI，未进行 Xcode 构建 |

Linux GTK 画板设置为不获取编辑器焦点，候选通过 IBus 提交，不用剪贴板或模拟按键；实际焦点行为仍待桌面验收。缺少 GTK 时不影响原键盘处理。本轮未执行 Linux 安装脚本；该脚本会注册组件并重启 IBus，需按原安装手册操作。

## 构建与验收命令

从仓库根目录执行，Android SDK/NDK、Rust targets 和已编译 librime 按 [构建手册](构建与验收.md) 准备。若要重建 Rime，先执行该手册的依赖构建步骤。

```bash
./tools/verify.sh
cargo build -p ime-ffi --release
python3 tools/verify-handwriting-model.py target/release/libime_ffi.so
source tools/android-env.sh
ANDROID_RIME_ROOT="$PWD/target/android-rime" ./tools/build-android-core.sh
cd platform/android-ime
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
```

APK 在 `platform/android-ime/app/build/outputs/apk/debug/app-debug.apk`。安装测试 APK 后再执行设备验收；只使用明确选定的专用测试设备。脚本不下载模型、不自动清理用户数据：

```bash
export ANDROID_SERIAL=emulator-5554
adb install -r platform/android-ime/app/build/outputs/apk/debug/app-debug.apk
adb install -r platform/android-ime/app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
./tools/verify-android-handwriting.sh
```

首次离线验收应在专用模拟器清除本 App 的旧测试数据后，禁用 Wi-Fi/移动数据，确认 `adb shell dumpsys connectivity` 中 `Active default network: none`，再安装和运行。清除应用数据会删除该模拟器中的词频、设置及缓存，不应对日用设备自动执行。

## 本轮证据

- `tools/verify.sh`：68 项测试通过，2 项依赖外部 whisper 模型的测试忽略；格式、严格 Clippy、C ABI smoke、TSF 核心边界探针通过。Cargo 缓存自动清理有既存权限警告，未影响退出状态。
- 公共模型回归：23 个源 XML 样例 Top1/Top5 均命中，前五候选与原版 C++ Zinnia 完全一致。这些是训练源回归，**不是独立真实用户准确率评测**；不能据此声称“准确率 100%”。
- Android `arm64-v8a`、`armeabi-v7a`、`x86_64` 含原生 Rime 与手写引擎构建通过；`assembleDebug`、`assembleDebugAndroidTest`、`lintDebug` 通过。Lint 为 0 错误、3 警告（构建工具更新提示和两个程序化 View 的工具构造函数提示）；Gradle assets API 另有弃用提示。
- 专用 `zhimo_visual_api35` / API 35 x86_64 模拟器：清除该 App 测试数据、禁用 Wi-Fi/数据、确认无默认网络后安装新版。14 项会话/键盘/原生 Rime 测试、2 项真实模型测试（含损坏缓存恢复）、1 次真实画笔候选上屏测试均通过，无跳过。最后一项重复执行键盘测试并启用真实笔迹，不计为新的独立测试方法。测试后恢复原系统输入法和网络开关。
- APK 签名校验、三 ABI ELF/依赖检查、原生 Rime 必需检查通过；包内模型与 XML 哈希一致，许可证/对应源文件齐全，权限只列出 RECORD_AUDIO，没有 INTERNET。语音服务联网边界见前文。
