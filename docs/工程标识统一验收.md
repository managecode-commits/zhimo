# 工程标识统一验收

工程源代码、文件名、包名、接口符号、Rime schema、构建变量、脚本及文档统一采用 Zhimo。重新扫描所有待版本管理的文件内容和路径，未发现旧品牌标识。Rust crate 的通用 `ime-*` 名称与第三方模型名称保持不变。

这是技术标识迁移，不只是应用显示名更新。Android 使用新应用 ID `dev.zhimo.ime`，JNI 使用 `Java_dev_zhimo_ime_*`，内部 Rime C 桥接使用 `zhimo_rime_*`，公开通用 `ime_*` C ABI 保留。旧应用、旧模型缓存与旧词库不会被删除或自动迁移；请保留旧应用，另行启用新版。详情见 [品牌与兼容标识](品牌与兼容标识.md)。

开发工作区目录、SDK/JDK/AVD 以及 Git 历史与旧远程地址未批量改名。历史验收文档的名称已统一，但旧包的哈希和测试结论只属于旧产物。

## 编译与静态检查

- Rust 格式、Clippy、工作区测试、C ABI 冒烟和 TSF 核心边界探针通过。需要外部音频/模型环境的语音集成用例仍按其既有规则跳过，不声称语音端到端验收完成。
- Linux IBus Python 编译和 Runtime 冒烟通过；Fcitx 5 在新构建目录生成 `libzhimo.so`，动态依赖检查未报告未解析符号。
- Android 三 ABI 核心以 native-librime 功能重建；`assembleDebug`、`assembleDebugAndroidTest`、`lintDebug` 通过。签名及 ELF 依赖检查通过，APK 内三个桥接库均导出新 JNI 名称，无旧包路径或桥接库名。
- 未在 Windows/macOS/iOS 真机上构建或验收完整客户端；Apple Xcode 工程仍需按文档组装。
- 拼音词汇“输入法”的测试输入使用 `shu'ru'fa`，不将自然语言拼音替换成品牌拼音。
