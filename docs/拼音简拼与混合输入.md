# 拼音简拼与混合输入

Copyright © 2026 立方田 <managecode@gmail.com>

## 支持范围

公共自研拼音核心支持词典内多音节词的首字母简拼、全拼/简拼混输，以及 zh/ch/sh 双字母声母。Android 9 键和 Windows 使用该核心；Android 26 键和 Linux 的 Rime 方案同步增加拼写规则。

| 类型 | 示例 |
| --- | --- |
| 首字母简拼 | nh → 你好，wm → 我们，zg → 中国，wlw → 物联网 |
| 混输 | nih / nhao → 你好，wulw → 物联网 |
| 双字母声母 | zhg → 中国 |
| 手动分词 | n'h / ni'h → 你好 |
| 9 键简拼 | 64（nh）→ 你好，96（wm）→ 我们 |

9 键重码多，目标词不保证第一位；可展开候选或通过侧栏选择拼音。独立单字的简拼不在此次新增范围内，原有单字前缀补全继续保留。

## 匹配和排序

- 自研核心保留全拼前缀索引，新增按首字母/首数字分桶的音节匹配索引。用位置位集逐音节匹配，不枚举所有混输组合；简拼匹配上限为 32 个音节、127 个输入字节。
- 完整拼音精确匹配优先；同类候选结合用户频率、词典权重排序，再处理前缀补全。9 键候选过多时，在前 15 个候选之后为最多 5 个简拼词预留位置，防止简拼词被单字挤出。正常词和逐字选词可能显示同一个字，但消耗的拼音长度不同，不能只按显示文字合并。
- 已选简拼词记录输入签名和完整读音。自组词恢复后可从完整读音匹配简拼，密码等受限输入保持原有不学习策略。
- 自研候选沿用完整读音注释；Rime 开启 spelling_hints 和 always_show_comments。
- Rime 使用官方示例中的 abbrev 规则；额外移除独立 m/n 鼻音拼写，避免 nhao 被解析为“嗯好”并屏蔽“你好”。“嗯”仍可输入 en。保留 a/e/o 等独立元音音节。

Rime 规则参考：[官方最小方案](https://github.com/rime/librime/blob/master/data/minimal/luna_pinyin.schema.yaml)；读音注释参数参考：[官方 script translator 实现](https://github.com/rime/librime/blob/master/src/rime/gear/script_translator.cc)。两个引擎使用各自的排序和学习实现，不承诺完全相同的候选顺序。

## 验证

- 自研拼音核心：25 项测试通过，含 26 键、9 键、混输、非法边界、选词学习、重启后组词简拼恢复和原有输入回归；性能测试另行运行。
- FFI：8 项测试通过；真实语音录音测试因缺少所需环境变量跳过。最初默认临时目录导致持久化写入失败，改用工程磁盘临时目录后通过。
- Ubuntu 24.04 容器中的真实 librime：12 个全拼/简拼样例的候选及选择上屏通过，简拼“你好”的完整拼音注释通过。
- 本机 release 模式：首次初始化两个索引并执行 6 次查询约 926ms；之后 120 次查询合计约 568ms，平均约 4.7ms。该结果包含初始词典加载，不代表手机延迟；手机首用延迟和输入体验仍需实机验收。
