# 桌面手写画板优化与 APK 经验复用

Copyright © 2026 立方田 <managecode@gmail.com>

## 本轮实现

- Windows：扩大候选区、26 像素候选字体、多列多行及横向滚动；新增重新识别；浅色十字辅助线、柔和笔迹与单点显示。语音界面不显示手写候选区。
- Linux GTK：8 列候选网格、较大候选字体和纵向滚动；新增重新识别；浅色辅助线、圆角笔迹和单点显示。
- 保留单字定位、显式点选上屏、异步识别和过期结果丢弃。辅助线不是分字边界，不要把偏旁当成多个字。
- 共享 Rust 离线识别底座迁移 Android `HandwritingShapeRanking` 的天／夫几何判别经验：仅四笔且模型前三名包含天或夫时检查，模糊接触区域不调整。桌面实现更加保守，目标字必须已经存在于候选中，不新增模型未给出的字。

## 参考图布局调整（2026-09-15）

按用户提供的桌面手写截图重新组织两端：左侧单字／离线状态栏，顶部候选区，中部浅色细网格大画板，底部常用标点、撤一笔、重写、重新识别及关闭。保留 Zhimo 名称，不复制第三方品牌或服务来源文字。空白画板提示写一个完整汉字，网格不用于分字。标点为显式点击上屏，关闭后忽略点击。

Windows 画板为 646 × 280 逻辑坐标，候选区仍可滚动查看更多；GTK 画板最小 640 × 280，并保留多行候选网格。参考图中的多字连写、袋鼠手写入口未添加，因为桌面识别底座尚未实现对应能力。

## 尚未迁移的能力

桌面仍是单字 Zinnia 笔迹识别，不等同于 APK 的图像模型融合、自由连写分字、逐字纠错及个性化校正。不能把此次局部规则修正宣传为整体准确率提升或 APK 能力完全对齐。

下一阶段应把比、观、动、从、响、天／夫及相似负样例整理成带目标字的真实笔迹回放集，再迁移图像识别与融合排序。截图可辅助标注，但不能精确还原真实笔顺、断笔和时序。验收需同时比较 Top-1、Top-5、Top-20、延迟及错误拆字率，避免为几个字增加无条件硬编码。

## 验证和交付边界

2026-09-15 已重新构建并交付至 `target/packages/zhimo-desktop-handwriting-20260915/`：Windows x64/x86 ZIP、Ubuntu 24.04 amd64 与 Debian 12 amd64 DEB（core + IBus/Fcitx5）。Linux 包版本为 `0.1.0~beta.20260915.2.<发行版>`；新核心库包含本轮排序修正，画板包含参考图布局。两种 Linux 发行版完成容器内 GUI 冒烟、拼音回归及安装／卸载检查；不等同于真实桌面会话验收。Windows 已检查双架构及依赖，实机输入仍待验证。旧产物保留。

共享底座 7 项单元测试及 C ABI 模型回归通过，参考图改版后 Windows 面板交叉编译、Python 语法检查通过。GTK 画板冒烟测试在临时 Ubuntu 容器补齐 cairo 后通过，覆盖画板绘制、单点、清空、标点上屏和关闭保护；GUI 测试使用已有 Debian 构建的兼容 ABI 库，不代表新识别核心已重新打包。真实鼠标／触屏书写和 Windows DPI 视觉仍需实机验收。先前发布的 ZIP、DEB、APK 不会随源码修改自动更新，本轮变更需重新构建核心库和对应平台包后才会生效。
