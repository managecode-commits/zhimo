# Android 内置离线语音

最新语音优化、VAD、确认上屏与测试边界见 [语音转录优化与验收](语音转录优化与验收.md)。下文保留初次交付记录，模型每次释放等描述不再代表当前实现。

最新版本入口已改为空格键长按，顶栏恢复左右布局切换；轻点停止录音并转录，识别中轻点取消。详见 [全国行政区词条与空格语音交付](全国行政区词条与空格语音交付.md)。下文的麦克风按钮及安装包信息为原始交付记录。

## 使用和范围

安装包：[zhimo-offline-speech-debug.apk](../platform/android-ime/app/build/outputs/apk/debug/zhimo-offline-speech-debug.apk)，180,873,434 字节（约 172.5 MiB），包名 `dev.zhimo.ime`，Debug 签名。SHA-256：`74a6a9a7560ba3684a01f1ba23ac938b85fcb5b56eb37fc7726459f9781c35cb`。同签名 Zhimo 可覆盖更新；旧包名应用需另行启用新版，请先保留旧数据。

默认开启“使用内置离线语音模型”。授予麦克风权限后，点击键盘麦克风，等待状态显示“聆听中”再说话；点击原麦克风位置的方框停止按钮结束录音并转录，识别中点击“取消”可中止。中文键盘使用 `zh`，英文键盘使用 `en`，不翻译。最长录音 60 秒，到时自动转录。

模型和推理库随包提供，首次使用在后台校验并安装到应用私有 no-backup 目录，安装后断网可用，不要求 Google 或手机厂商语音服务。不会静默回退联网服务；只有明确关闭内置模式后才使用原系统识别路径，其联网开关继续独立生效。密码框禁止语音；未提交拼音/手写需先处理。

本轮实现 Android 停止后转录，不是五端同时完成，不提供流式中间结果。模型为多语种 Whisper Base Q5_1，59,707,625 字节；较大或不同模型需独立评测，不把量化后的体积等同准确率。中文可能输出繁体，当前不做繁简转换。中英混说、方言、噪声、轻声、数字标点和长句准确率尚需独立评估。

## 实现

- `OfflineSpeechModel`：固定 SHA-256、大小、私有存储、临时文件校验与原子替换，损坏模型从 APK 修复；模型不进入自动备份。
- `OfflineDictation`：AudioRecord 16kHz 单声道 PCM16，单工作线程，最多 60 秒，结束与取消分离，录音和推理不占用 UI 线程。
- `offline_speech.cpp`：库级 JNI 调用 whisper.cpp，不启动 shell 或外部进程；两个 CPU 线程、推理回调取消与 120 秒截止。加载模型阶段不能立即中断，但取消后不会提交文字。
- 模型在每次推理结束释放，减少输入法常驻内存，代价是每次需要重新加载。原始录音只在内存中，不写 WAV、不上传、不写入日志；测试仅记录公开样例结果。
- 回调使用任务身份校验；切换/关闭输入框、隐藏键盘、切换模式或光标位置改变会取消当前任务。最终文字通过已有 `NativeIme.speechResult` 和 Runtime 上屏，保留密码域防护。
- 数字静音能量门限只避免完全静音幻觉，不是完整 VAD；没有自动静音断句。后台回收、来电、录音竞争与低内存仍须真机覆盖。

模型来源、版本和许可见 [manifest](../models/speech/manifest.json)、[第三方模型说明](../models/speech/README.md)。权重与 whisper.cpp 均保留 MIT 许可文件；本项目代码许可不替代它们。

## 构建

在仓库根目录运行：

```bash
bash tools/prepare-offline-speech.sh
# 主站受限时可用相同哈希校验的公共镜像：
# ZHIMO_MODEL_HOST=https://hf-mirror.com bash tools/prepare-offline-speech.sh
./tools/verify-android-rime-beta.sh
```

已有三 ABI 核心库时可只重建 Android：

```bash
source tools/android-env.sh
cd platform/android-ime
./gradlew --no-daemon :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug --max-workers=2
```

权重不提交到 Git；新 clone 必须先执行准备脚本。Gradle 强制校验权重及许可，缺失时构建失败，不生成假“内置”包。APK 验证脚本检查三 ABI 的 `libzhimo_speech.so`、模型哈希及许可文件。生产发布仍需所有者 Release 签名和真机验收。

## 可复现测试

`OfflineSpeechTest` 默认测试模型安装/损坏修复、静音、无效音频与取消状态。真实语音测试需显式 `-e runOfflineSpeech true`，读取测试 App 外部文件目录 `speech-test/en.wav`、`speech-test/zh.wav`；格式为 PCM16、单声道、16kHz、最多 60 秒。样例不进入产品 APK，也不读取用户私人录音。

本轮公开样例来源：

- 英文：固定 whisper.cpp 1.9.1 源码中的 `bindings/go/samples/jfk.wav`。
- 中文：[sherpa 官方示例引用的 AISHELL2 音频](https://github.com/k2-fsa/sherpa-onnx/blob/master/python-api-examples/speech-recognition-from-url.py)，地址 `https://huggingface.co/spaces/k2-fsa/automatic-speech-recognition/resolve/main/test_wavs/aishell2/ID0012W0030.wav`。仅本地冒烟测试，不随源码或安装包再分发。

`-e runOfflineMic true` 额外验证麦克风开始、结束、取消回调；需测试设备已授予 `RECORD_AUDIO`，完成后由测试操作者恢复原权限。不得在未授权用户设备上自动录音。中英文公开样例通过也只代表模型推理链路可用，不是 CER/WER 或多人真机验收。

示例（已安装主包和测试包，在自己授权的测试模拟器上执行；`en.wav` / `zh.wav` 为上述格式的授权样例）：

```bash
adb -s emulator-5554 shell mkdir -p /sdcard/Android/data/dev.zhimo.ime/files/speech-test
adb -s emulator-5554 push en.wav /sdcard/Android/data/dev.zhimo.ime/files/speech-test/en.wav
adb -s emulator-5554 push zh.wav /sdcard/Android/data/dev.zhimo.ime/files/speech-test/zh.wav
adb -s emulator-5554 shell am instrument -w \
  -e runOfflineSpeech true \
  -e class dev.zhimo.ime.OfflineSpeechTest \
  dev.zhimo.ime.test/androidx.test.runner.AndroidJUnitRunner
```

上述命令不会录制麦克风；仅在需验证录音且已授权时额外传 `-e runOfflineMic true`。
本轮样例 SHA-256：英文 `59dfb9a4acb36fe2a2affc14bacbee2920ff435cb13cc314a08c13f66ba7860e`，中文 `f042c6cd8cb7fc745f37805565b5ce41b9a4f38a54b267e1a9afd806d5216a38`。

## 实测记录

第一轮 API 35 x86_64 断网模拟器专项测试 6 项通过，覆盖上述所有 OfflineSpeechTest 分支；麦克风启停使用禁用宿主音频输入的模拟器，不能代替真机麦克风音质测试。真实模型英文结果包含 `country`，中文输出“完全是典型的軍事侵略”。中文测试断言目前仅检查汉字输出，尚无独立校验的参考转写，不把该样例记作准确率满分。

本机同时运行编译任务时，Android 两个公开样例的单次模型调用耗时分别约 35.4 秒与 27.6 秒，包含加载与推理。这只是受资源竞争影响的模拟器记录，不是手机基准，不能据此承诺实时性能。

同一模型用于桌面 `tools/verify-whisper-cpp.sh`：Rust Whisper Provider 和 C ABI 的两项真实音频集成测试均通过（不再忽略）；这仍不代表桌面输入法已接通麦克风。

最终主包、测试包和 Lint 构建通过；Lint 为 0 errors、13 warnings。APK 签名、三 ABI 动态依赖、模型 SHA-256 与许可检查通过，模型和三 ABI 语音库均实际位于包内，不是占位文件。

最终断网模拟器回归 `OK (39 tests)`：8 项 Runtime、4 项手写会话、4 项手写面板、2 项轨迹模型、4 项图像模型、10 项连写、6 项离线语音与 1 项实际键盘 UI 流程全部通过。UI 流程包括数字/字母手写上屏、语音开始/停止及移动光标取消，取消后不会写入迟到结果。最终公开音频单次调用约 26.1 秒（英文）、20.1 秒（中文），仍只作模拟器观察值。
