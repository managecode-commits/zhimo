# Android 键盘视觉与一级表情入口

后续变更：顶栏麦克风已换为左右布局切换，录音改由空格长按进入，见 [最新交付说明](全国行政区词条与空格语音交付.md)。下文为此前版本记录。

## 本轮调整

- 空闲顶栏：9/26 键、123、符号、手写、中英切换、表情、语音。Emoji 取代单手快捷键，不额外增加按钮数量。
- 单手设置保留在主应用设置；候选工具菜单增加单手切换，空闲时也可长按表情键打开工具菜单。
- 有候选仍共用原顶栏，不新增常驻候选空白行；窄屏顶栏横向滚动，按钮保持最小宽度。
- 明确字符、功能、分类、表情、主要操作五种样式角色。字符用中等字重，功能用常规字重、较浅背景。
- Emoji 和分类标签使用轻量背景；分类选中时同时显示背景高亮和下划线，高对比模式保留高对比底色。
- 数字、符号、Emoji 的编辑器动作统一跟随输入框；中文返回显示“拼音”，英文显示“ABC”。
- 表情从手写进入可返回手写，从文字进入可恢复文字模式。切换前仍执行原有未确认输入保护。
- Emoji 使用固定高度内容区，分类横向滚动、内容纵向滚动；列数按可用宽度和文字缩放调整。
- 表情底栏保留返回、空格、删除、编辑器动作四键；数字和符号由顶栏进入，避免窄屏重复入口挤占空间。
- 最近记录仅在切换分类或重进面板时重新排序，连续点选不移动按钮。清除记录移入“最近”，需点击确认菜单。
- 密码和不允许学习的输入继续不读取、不记录最近表情；所有 Emoji 仍为离线 Unicode 文本。

## 验收范围

自动测试包含一级入口、表情连续上屏、完整删除、最近清除确认、返回拼音、表情与 26 键高度一致，
以及与 9 键高度一致、返回手写和已有拼音/手写/连写/数字字母流程。
另检查窄屏和大字模式；不代表所有手机或辅助技术均已完整验收。
模型未修改，本轮不增加任何手写准确率承诺。

第一次实际 UI 验证发现 26 键与表情页高度相差 1 像素：`dp(行高*3)` 与 `dp(行高)*3`
在非整数屏幕密度下取整不同。统一按单行像素累加；9 键板也使用相同计算，不放宽高度相等断言。
首轮失败日志保留为 `target/zhimo-visual-ui-standard.log`，不计入最终通过结果。

后续首次显示还发现 126 像素导航栏留白晚于窗口测量，按键区域被裁切。
现在第一次测量即使用已知导航栏留白；留白变化后在分发结束外请求完整布局，不重建手写面板。
高度断言改为比较明确标识的按键容器，排除系统窗口装饰。中间失败记录保留在
`target/zhimo-visual-verified-ui-standard.log`、`target/zhimo-visual-delivery-ui-standard.log`。

## 中间验收（导航修正前，不作为最终交付包）

- API 35 x86_64，中间 APK 的 33 项样式、表情、手写测试通过（34.237 秒）。
- 标准布局完整键盘交互通过（69.948 秒），包含真实离线手写、连写及拼音。
- 320dp 宽屏幕（840px / 420dpi）、大字、高对比度、左手模式组合交互通过（46.899 秒）。
  此配置没有重复注入真实笔迹，不将它算作独立手写准确率验收。
- 标准及窄屏均验证 26 键、9 键与表情的按键容器高度相等，并检查表情连续输入、完整删除和返回输入模式。
- 清最近确认流程在标准布局验证；大字窄屏的分类栏需要横向滚动，工具栏末端也可能需要横向滚动。
- 实际截图：`target/zhimo-visual-standard-emoji.png`、`target/zhimo-visual-narrow-emoji.png`。

本轮不代表所有手机、所有导航模式、TalkBack 或超大系统字体均已验收；这些仍需真机覆盖。

深色模式虽通过原操作流程，截图仍显示系统导航按钮覆盖底栏。核对
[AOSP 输入法导航控制器](https://github.com/aosp-mirror/platform_frameworks_base/blob/android15-release/core/java/android/inputmethodservice/NavigationBarController.java)
后，留白计算同时考虑 `navigationBars` 和 `captionBar`。新增底栏可见高度和导航区域不重叠断言，
不能仅凭候选上屏或两种模式高度相等就判断底栏正常。
旧中间包移至本机 `target/zhimo-keyboard-visual-pre-nav.apk`，不作为交付入口。
