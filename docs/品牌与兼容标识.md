# Zhimo 工程名称与迁移

产品为「知墨输入法 / Zhimo IME」，通用底座为「Zhimo Core」。源代码、文件名、配置、测试和文档统一使用 `zhimo`、`Zhimo`、`ZHIMO`，不再保留旧品牌的兼容别名。第三方库、模型文件和授权归属不更名。

| 范围 | 新标识 |
| --- | --- |
| Android | `dev.zhimo.ime`、`ZhimoInputMethodService`、`libzhimo_android.so`、JNI `Java_dev_zhimo_ime_*` |
| C 接口 | `include/zhimo_ime.h`、`ZHIMO_CAP_*` 常量、内部 `zhimo_rime_*` 桥接函数；公开 `ime_*` ABI 与 `libime_ffi` 名称不变 |
| Apple | `ZhimoCore`、`ZhimoSession.swift`、`ZhimoCore.xcframework` |
| Linux | `zhimo` 输入引擎、配置文件和插件、`org.freedesktop.IBus.Zhimo` |
| Windows | `ZhimoTsf.dll`、`CLSID_ZhimoTextService`、`GUID_ZhimoProfile` |
| 配置 | `ZHIMO_*` 环境变量、`ZHIMO_ROOT` 等构建参数、`zhimo` 数据目录 |

## 升级注意事项

- Android 新包名代表新应用，不能覆盖旧包名应用；旧设置、词库和启用状态不会自动迁移。保留旧应用和数据，在系统设置中另行启用“知墨输入法”。不要为安装新版而先卸载旧版。
- JNI 与内部 Rime 桥接符号已变更，相关组件必须重新编译链接。公开 `ime_*` C ABI、版本数值及结构布局不变；C/C++ 调用方需更新头文件路径与能力常量名。完整构建仍重建各 ABI 核心，避免缓存混用。
- Linux 需重新构建、安装并添加新输入源，旧输入源和数据不自动删除或迁移。
- Windows GUID 数值保持不变，避免改变既有 COM 产品身份；符号名和 DLL 文件名已更新。已有安装应先按旧安装位置注销旧 DLL，再注册新版，旧用户数据保留，不自动复制。
- Apple 工程需更新模块引用、源码路径、连接名称和资源；仓库没有完整 Xcode 应用工程，已有 Bundle ID/App Group 应由工程维护者明确处理。
- 本地开发工作区目录、Git 历史和旧远程仓库地址不属于源码标识替换范围；不改写历史或删除远程。旧安装包、SDK、AVD、构建缓存和个人数据保留，不批量改名。建议从 GitHub 克隆到名为 `zhimo` 的新目录构建。
- 重新构建时使用新环境变量名。旧缓存可能保留旧符号，必须重建核心与平台桥接库。
