# 桌面发行打包与验收

## 交付边界

这些是开发测试包，不是已经完成所有平台验收的正式发行版。
Windows 双架构包为 x64 Windows 上的 x64/x86 TSF 插件，Linux 为 IBus / Fcitx5 插件，不是双击启动的独立编辑器。
不得把交叉编译、容器编译成功等同于真实桌面应用兼容性通过。

| 能力 | Windows x64 | Linux IBus | Linux Fcitx5 |
|---|---|---|---|
| 拼音 | 参考引擎、本地学习 | 发布包默认完整 Rime | 发布包默认完整 Rime |
| 完整项目词库 | 未统一到 Rime | 随 core 包安装 | 随 core 包安装 |
| 手写 | 独立单字画板 | GTK 单字画板，非 Android 连写体验 | 共用独立 GTK 单字画板 |
| 离线语音 UI | 独立预览确认面板 | 独立预览确认面板 | 共用独立预览确认面板 |
| 独立统一设置 | 未完成 | 未完成 | 未完成 |

## Linux：在目标发行版构建

需要 x86_64 Linux、Docker、项目固定 Rust 工具链。先 `cargo fetch --locked` 缓存依赖。
构建下载只发生在 Docker 镜像准备阶段；源码只读挂载，Rust 编译阶段禁用网络。
不挂载 Docker socket、GitHub 凭据或整个用户主目录。

```bash
bash tools/build-linux-deb.sh debian12
bash tools/build-linux-deb.sh debian13
bash tools/build-linux-deb.sh ubuntu2204
bash tools/build-linux-deb.sh ubuntu2404
```

Docker Hub 不可达时，可选择 [Ubuntu 官方列出的 ECR 分发源](https://ubuntu.com/docs/oci-registries/oci-how-to/getting-started/)，无需修改 Docker 守护进程配置：

```bash
ZHIMO_LINUX_BASE_IMAGE=public.ecr.aws/ubuntu/ubuntu:24.04 bash tools/build-linux-deb.sh ubuntu2404
```

脚本会核对基础镜像的实际发行版与版本，并在 BUILD-INFO.json 记录所用镜像；
如需固定基础镜像，可将 tag 替换为已验证的 `@sha256:...` 摘要。

每次创建新的 `target/zhimo-<发行版>.<随机值>/packages`，不覆盖旧产物。
目录包含 `zhimo-core`、`zhimo-ibus`、`fcitx5-zhimo` 三个 deb 与 BUILD-INFO.json。
glibc 上限分别为 2.36、2.41、2.35、2.39；这是构建门禁，不是跨发行版兼容保证。
Fcitx5/Rime 依赖由构建发行版的 dpkg-shlibdeps 计算。每个发行版使用自己的产物。
只读模型、Rime schema / 项目词库放在 `/usr/share/zhimo`，本机代码在 multiarch `/usr/lib` 中。
默认启用 Rime 的前提是运行库包含 native-librime 且系统资源存在；显式 Rime 环境变量仍优先。

安装时在该目录任选与当前桌面使用的框架匹配的一组：

```bash
# IBus，例如 Ubuntu GNOME 默认桌面
sudo apt install ./zhimo-core_*.deb ./zhimo-ibus_*.deb
# 或 Fcitx5：不要因此在同一会话并行启动两个输入法守护进程
sudo apt install ./zhimo-core_*.deb ./fcitx5-zhimo_*.deb
```

安装不自动修改会话、重启输入法或强制切换默认键盘。注销登录后，在系统输入源设置或
Fcitx5 配置界面添加 Zhimo。X11 / Wayland、GTK / Qt 须分别测试。
升级时安装同一版本的 core 和所用插件；卸载用 `sudo apt remove zhimo-ibus` 或
`sudo apt remove fcitx5-zhimo`，不自动删除个人词库。

手动 GitHub Actions 工作流 `Desktop packages (manual)` 为四发行版生成独立产物。
新增工作流文件不表示已经在 GitHub 成功运行。

## Windows：版本目录与诊断

参考 `platform/windows-tsf/TEST-INSTALL.md`。包内包含依赖 DLL、探针、安装/卸载、
EmEditor 焦点诊断、安装版本诊断及 SHA256SUMS.json。
首次运行 install.cmd；已安装用户需显式在管理员 PowerShell 执行 `./install.ps1 -Upgrade`。
旧目录保留，升级不覆盖正被应用加载的 DLL；注册失败时尝试重新注册旧 DLL。
自动恢复失败须保留输出和文件，切回微软拼音，不继续反复覆盖注册。
正常升级后必须注销登录。卸载从已安装的精确版本目录执行，不从下载目录执行。
包未签名；不要关闭系统安全功能。当前未提供 x86、ARM64、MSI 或自动更新。

## 发布前必须补齐的实机验收

1. Windows 10/11 x64：首次安装、旧包升级、失败恢复、卸载；确认磁盘与已加载版本。
2. EmEditor、记事本、浏览器、Office：nihao、lvdai、wulianwang，候选点击、翻页、退格、焦点切换。
3. 密码/PIN 不拦截、不学习；多窗口、中文/英文切换、DPI 100/150/200%。
4. 每个 Linux 发行版：干净安装、升级、卸载，IBus/Fcitx5 分开验证，GTK/Qt、X11/Wayland。
5. Rime 首次部署耗时、用户词典持久化、缺失或损坏资源时的错误提示。

桌面手写/录音界面、统一设置、Windows 完整 Rime、签名与上述实机测试仍是后续工作，
不能用 Android 的验收结果替代。
