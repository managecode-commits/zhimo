# 手写输入架构与验收

> 历史记录：本文件描述上一轮 Google ML Kit 路线。用户已选择改为内置离线模型，当前实现、限制、构建和新 APK 以 [内置离线手写交付](内置离线手写交付.md) 为准；下文下载入口及多语言选项已移除。

日期：2026-09-13。手写是独立输入能力，不是拼音字库或 librime 的开关。

## 产品目标与当前边界

最终形态：中文单字、横向连续词句、可选重叠书写；英文、数字、符号与更多语言通过能力声明扩展。
候选点选后上屏，自动上屏默认关闭。单字、连续书写、重叠书写必须分别评测。

当前代码新增：

- Rust `ime-handwriting`：无 UI、无联网的笔画/Provider 契约、会话版本保护、候选过滤与输入数据限制。
- Android：手写模式、画板、简体/繁体/英文模型切换、明确的下载按钮、撤一笔/清空、候选点选、返回键盘。
- Android `MlKitHandwritingProvider`：真实 Digital Ink SDK 接入，不用假候选冒充模型。
- Android 使用对应的 Kotlin 会话实现；**尚未通过 JNI 接入 Rust 手写模块**。Rust 模块是可测试的通用基础，不代表其他平台手写功能已完成。

尚未交付：Windows/Linux/macOS/iOS 的手写 UI 与识别器适配、重叠字分割、模型个人字形训练、手写候选长期学习、自控可再分发跨平台模型、全量准确率/真机/无障碍验收。

## 架构与契约

平台画板 → 规范化笔画 → 手写会话 → Provider → 候选 → 平台确认提交。

笔画包含 x/y、单调毫秒时间，坐标与 WritingArea 使用同一坐标系。不得将多个字分别缩放后叠在一起。
Rust Request 带 session/revision/language/width/height/strokes；Provider 声明语言、离线、单行与重叠能力。
Provider 不得操作输入框、候选 UI 或用户数据库。模型安装与识别分开，下载只能由明确操作触发。

安全规则：

1. 每个输入框生命周期使用独立会话。落笔即更新 revision，而非等抬笔才使旧候选失效。
2. 清空、撤销、换语言、换模式、收起键盘、切换输入框都取消旧结果的提交资格。
3. Android 每个 Provider 实例最多一个识别请求在途；后续笔画完成后合并请求，不对每个移动点推理。
4. 候选携带请求版本；点选时再核对。提交返回成功才清除笔画，失败保留候选供重试。
5. 限制 128 笔、每笔 4096 点、20 个候选；拒绝非有限坐标、空笔画、倒退时间、控制字符。
6. 密码输入禁用手写；不读取周边文本、不保存原始笔迹、不自动学习、不记录识别文字日志。

Android 画板退出会丢弃未确认笔迹，不自动上屏。撤一笔仅修改画板；退格仅删除输入框文字。
空格/回车先清理未确认笔迹，再执行输入框动作。按钮区与画板区相互独立。

## 模型、网络与授权

依赖 `com.google.mlkit:digital-ink-recognition:19.0.0`，语言使用官方模型表的
`zh-Hani-CN` / `zh-Hani-TW` / `en-US`。官方支持表不能替代各语言效果实测。

第一次使用需点“下载模型”；下载后笔迹识别在设备执行。未下载或下载失败会展示状态，不伪造识别结果。
设置中的“启用 Google ML Kit 手写识别”默认关闭；先阅读指标上传与隐私说明并开启，再回到键盘下载模型。
未开启时不创建手写识别器，但不能由此保证打包 SDK 的初始化组件完全没有网络行为。
本次新增 INTERNET 权限，因此不能再把 APK 描述成“没有联网能力”。SDK 自身的数据收集、模型服务访问
及发布披露应按官方条款审查，不能把“本地识别”扩大解释为“SDK 永不发送任何数据”。
本项目 Apache-2.0 许可证不覆盖 Google SDK/模型，不把官方模型抓取后擅自打包再分发。

正式上线前需确认目标网络可达性、SDK 数据安全披露、第三方条款及模型下载后的离线行为。
用户先前接受 Android SDK 许可证不等于已经接受所有新增第三方模型再分发条款。

## 构建与测试

```bash
cargo test -p ime-handwriting
cargo clippy -p ime-handwriting -- -D warnings
source tools/android-env.sh
cd platform/android-ime
./gradlew --no-daemon --max-workers=2 :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
```

若宿主机 IPv6 连接超时而 IPv4 正常，可在 Gradle 命令中追加
`-Dorg.gradle.jvmargs='-Xmx768m -XX:MaxMetaspaceSize=384m -Djava.net.preferIPv4Stack=true'`。
这只影响本次构建 JVM，不修改系统网络或换用非官方 Maven 来源。

安装 App 与 androidTest APK 后，在专用模拟器运行：

可先使用 `ANDROID_SERIAL=emulator-5554 tools/verify-android-handwriting.sh --download-model`
自动执行以下契约、UI、模型与上屏测试；不带 `--download-model` 时只使用已有模型。
脚本会检查 JUnit 成功标记，避免 `am instrument` 在测试失败时仍返回 shell 0 造成误报。

```bash
adb shell am instrument -w -e class dev.shurufa.ime.HandwritingSessionTest \
  dev.shurufa.ime.test/androidx.test.runner.AndroidJUnitRunner
adb shell am instrument -w -e requireNativeRime true -e runKeyboardUi true \
  -e class dev.shurufa.ime.KeyboardInteractionTest \
  dev.shurufa.ime.test/androidx.test.runner.AndroidJUnitRunner
# 显式允许测试下载简体中文模型；需要网络。不指定参数会跳过此用例。
adb shell am instrument -w -e downloadHandwritingModel true \
  -e class dev.shurufa.ime.HandwritingModelTest \
  dev.shurufa.ime.test/androidx.test.runner.AndroidJUnitRunner
# 仅在上一步真实模型测试成功后，验证画板触摸 → 候选“一” → 编辑器上屏。
adb shell am instrument -w -e runKeyboardUi true -e requireNativeRime true -e runRealInk true \
  -e class dev.shurufa.ime.KeyboardInteractionTest \
  dev.shurufa.ime.test/androidx.test.runner.AndroidJUnitRunner
```

真实模型用例只验证横线笔迹的候选包含“一”，不是准确率基准，更不代表姓名/连笔/生僻字全部支持。
正式质量门槛需要独立多人笔迹集，记录首选正确率、Top-5、连续书写字符错误率、P95 延迟、冷启动、内存与耗电。
