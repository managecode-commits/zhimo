## 本轮软件工程整改

| 范围 | 已落地 | 验收边界 |
|---|---|---|
| 质量入口 | 锁定依赖、格式、严格 Clippy、测试、C ABI/TSF 核心探针、发布契约检查 | 本地执行不代表远端 CI 已运行 |
| Android CI | 增加三 ABI、原生 Rime、离线资源、Lint、APK 构建任务 | 未代替真机 UI 测试 |
| 学习持久化 | SQLite 增量合并；单后台线程、单待写快照合并；失败状态查询；读取失败保护原数据库 | 快照复制仍在调用线程；显式 flush/free 仍可能阻塞；无定时重试 |
| 拼音学习查询 | 消除逐条嵌套扫描，使用借用记录和一次读音映射；非匹配记录提前过滤 | 大量个人词条仍需索引与目标设备性能验证 |
| 通用底座 | Rust 动作改名 ReadingOptions；保留 JSON PinyinReadings 兼容名称，增加异步学习 capability | 尚未完成语言包能力协商与跨引擎统一回退策略 |
| Android 解耦 | 动作解码独立为 InputActionDecoder，整批验证后再操作编辑器 | 不是完整输入状态机重构；服务类仍需拆分 |
| 词条维护 | “极简”等人工词条以 TSV 为唯一来源，生成 Rime 数据并校验一致性 | 不是所有领域词条均已覆盖 |
| 版本与打包 | Android 版本从 release/version.json 读取；Windows ZIP 保留完整版本名 | 其他平台版本尚未全部统一 |
| Windows 安装 | 下载阻止标记要求用户明确确认后解除，检查组织策略，不修改系统执行策略 | 脚本仍未数字签名，须在真实 Windows 验证 |
| 产物可追溯性 | 预构建 DLL 来源明确标为未验证，区分打包提交与二进制来源 | 尚未实现编译收据、签名与完整可复现构建 |

验证日志位于本机 `target/remediation-final-verify.log`、`target/remediation-android-final.log`，不随源码入库。当前 Android instrumentation 已编译，但没有连接设备运行。本轮没有重新验证 Windows 编辑器、Linux 桌面会话或 Apple 平台。

## 下一阶段必须完成的验收

1. Android：实机验证选词学习、重启持久化、异常存储提示、密码输入禁学、9/26 键及动作批处理。
2. Windows：下载 ZIP 后的确认安装、组织策略拒绝路径、x86 EmEditor 与 x64 应用；状态栏和手写/语音焦点切换。
3. Linux：Ubuntu/Debian 的 IBus/Fcitx 真实桌面加载、Wayland/X11 焦点与候选位置。
4. 性能：固定硬件、无并行构建、冷启动/热输入、大词库与个人词条规模分组基准；目前不能宣称达到统一延迟目标。
5. 识别：用独立、授权测试集报告手写 Top-1/Top-5 和语音 CER/WER、延迟及内存；历史截图修复不等于模型整体准确率达标。
6. 架构：继续抽离 Android 输入状态协调器、集中引擎选择/隐私回退、统一全平台版本与编译来源证明。

这些是明确保留的工作，不列为已完成。历史平台交付和旧版本证据见 [历史记录](实现状态历史-20260915.md)，不应将其中的旧测试数字当作本轮结果。
