# 拼音输入与 Android 键盘评估

> 复评日期：2026-09-13

## 结论

此前“能输入少量拼音、普通拼音没有汉字”的根因不是触摸坐标、JNI 或空格事件，而是 APK
默认 Rime schema 只打包了约百条项目验证词典。`nihao` 等样例能通过，但大量真实词汇没有
候选，空格只能提交原始拉丁字母，形成“拼音不了汉字”的直接体验。

当前修复后的 Android Rime APK 默认安装 `shurufa_pinyin` 全拼方案，使用锁定提交及
SHA-256 的 `rime-pinyin-simp` 离线词典（65,125 条记录），启用整句转换和本地用户词典。
9键及无 Rime 降级引擎由同一上游数据生成，并叠加187条项目常用词优先级，避免两种键盘
词汇覆盖严重不一致。

## 输入路径

| 模式 | 按键 | 输入引擎 | 空格行为 | 当前验证 |
|---|---|---|---|---|
| 中文26键 | QWERTY、拼音分隔符 `'` | 原生 librime；初始化失败才回退 | 有组合时选择首选，无组合时不插入多余空格 | `putao → 葡萄` |
| 中文9键 | `1='`，`2-9=ABC…WXYZ` | 通用参考/T9引擎 + 65,125条词典记录 | 有组合时选择首选 | `78826 → 葡萄` |
| 英文26键 | QWERTY、大小写 | Latin 引擎 | 插入空格/提交英文组合 | 自动化测试通过 |
| 数字 | `0-9 . , ? ! @ #` | 直接提交 | 字面空格 | 按键路由测试通过 |
| 常用符号 | 中文标点或英文/编程符号 | 直接提交 | 字面空格 | 模式隔离测试通过 |

数字和符号页不再把数字误送入9键拼音；切换语言、键盘页或26/9键前会清除未提交组合，
删除和回车会根据当前页面选择引擎事件或直接编辑文本框。

## UI 按键复评

- 候选栏固定显示当前模式（拼音26键、拼音9键、English、数字或符号），候选显示汉字与
  拼音注释，支持首选高亮及前后翻页。
- 中文组合存在时，底部空格键显示“选词”；提交后恢复“空格”，使按键显示与实际行为一致。
- 语言切换按钮显示“切英”或“切中”，无障碍描述使用完整动作，不再用含义不清的“中/英”。
- 中文工具栏提供26/9键、数字、符号、语言和语音；英文工具栏将布局键替换为大小写键。
- 数字/符号页提供明确的 ABC 返回键；符号页可在中符与英符之间切换。
- 回车键跟随编辑器显示搜索、发送、完成、下一项或前往；存在组合时事件先由输入引擎处理。

## 数据、学习与可复现性

- 26键 Rime 使用 `enable_user_dict` 和 `enable_sentence`，词频学习保存在应用私有 Rime
  用户目录；资源版本从2提升到3，旧安装会原子升级共享数据而不删除用户目录。
- 9键/降级引擎沿用通用 Runtime 学习记录，用户选择会改变后续候选排序；密码框及
  `IME_FLAG_NO_PERSONALIZED_LEARNING` 会禁止学习。
- `tools/update-rime-pinyin-simp.sh` 固定上游提交和两个 SHA-256，同时生成 Android Rime
  词典、许可文本及参考/T9 TSV。任何下载内容变化都会使脚本失败。

## 验收证据

- `./tools/verify.sh`：58项常规测试通过，2项需要外部语音模型的测试按设计忽略。
- `./tools/verify-android-rime-beta.sh`：三 ABI librime/Rust/JNI 构建、Android Lint、APK v2
  签名、ELF依赖和6项 API 35 instrumentation 测试通过。
- instrumentation 强制原生 Rime 输入 `putao` 并检查“葡萄”，同时验证65,125条回退词库
  中的“葡萄”“电视剧”“输入法”“人工智能”。
- 模拟器真实触摸验证：26键 `putao` 出现“葡萄”并通过“选词”键提交；9键 `78826`
  的首选为“葡萄”。

## 尚未等同于成熟商业输入法的能力

本次已经修复“普通拼音没有汉字”和按键语义问题，但65,125条基础词典不等于最终语言质量。
正式产品仍需要大语料词频重排、长句切分评测、模糊音/双拼、用户自造词管理、联系人及专业
词库（须单独授权）、中英数字混输、emoji/剪贴板、滑行与长按，以及 Android 8～17 真机
兼容、无障碍和性能矩阵。上述项目应以质量数据逐项验收，不能仅以“接口已存在”标记完成。
