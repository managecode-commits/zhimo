# Linux 桌面交互整改与验收

Copyright © 2026 立方田 <managecode@gmail.com>

## 本轮实现

- IBus、Fcitx5 的手写／语音 IPC 每 50 毫秒重新检查输入资格；失焦或变成敏感输入后取消子进程，不接收晚到结果。Fcitx5 因此不必等待下一次按键才发现敏感状态变化。
- Fcitx5 再次按面板快捷键改为关闭，与 IBus 快捷键一致。快捷键仍为 Ctrl+Shift+H（手写）、Ctrl+Shift+F10（语音）。
- 独立面板在当前用户运行目录使用非阻塞 flock，手写与语音、IBus 与 Fcitx5 共用单实例限制。锁文件不存文字、音频或笔迹，进程退出即释放；不删除活锁、不杀其他框架的进程。不安全的目录或符号链接会拒绝打开。
- 语音新增麦克风列表刷新、点击切换设备、输入音量指示。设备枚举在后台执行并设 3 秒超时；过滤扬声器 monitor 源；录音过程中禁止切换设备。音频仍只保存在进程内存。
- 包含只读安装诊断程序，检查会话类型、框架、安装版本、模型文件及音频工具。运行：`python3 /usr/lib/zhimo/bin/diagnose_desktop.py`。诊断输出环境设置，不读编辑器、不录音、不改配置。

## 交付与验证

新 DEB 版本为 `0.1.0~beta.20260915.3.<发行版>`，目标 Ubuntu 24.04 与 Debian 12 amd64；安装同版本 core 与所用的 IBus 或 Fcitx5 插件，不同时启动两套框架。

测试包括原有键盘／IPC／GTK 冒烟，新增失去输入资格取消、锁互斥释放、锁路径安全、音量计算、设备过滤、录音中禁止切换等检查。设备测试使用模拟列表，不代表物理麦克风已测试。

## 尚未完成，不能宣称全部平台验收通过

- 本环境没有真实 GNOME／KDE Wayland 桌面与用户麦克风；面板“不抢焦点”提示在目标合成器上的效果、状态入口可见性、录音设备故障恢复仍须实机测试。不会以放宽失焦保护换取可能错上屏的操作。
- 语音预览仍为只读确认，尚未加入可编辑文本控件：可编辑窗口需要取得焦点，必须先解决与当前编辑目标绑定／取消协议的兼容，不能直接取消失焦保护。
- 手写仍为单字笔迹模型及保守几何排序，没有完整迁移 APK 图像模型融合、连写分字和个人纠错。整体准确率仍缺带目标字的真实笔迹测试集，不能只凭截图或少量规则证明提升。
- 系统状态入口仍由 IBus／Fcitx5 和桌面环境呈现，没有新增跨桌面自绘悬浮状态栏。

实机验收顺序：确认状态菜单可见 → 普通输入框打开画板并点选 → 切换应用不误上屏 → 密码框不录音／不上屏 → 重复快捷键与多窗口不重复面板 → 测试选定麦克风、静音、断开 → 测试 GTK／Qt／浏览器的 X11 与 Wayland 组合。
