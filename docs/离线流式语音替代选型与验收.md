## 候选与包体积

- 第一候选：中英流式 Zipformer，`sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20`。上游与 ONNX 转换版模型卡均标注 Apache-2.0；该版本作为有明确来源的对照基线，不称为最新或最佳模型。量化编码器搭配所需解码器、joiner、tokens，不能把同目录全部训练与浮点文件打包。
- 对照候选：中英流式 Paraformer。官方文档中 INT8 encoder/decoder 合计约 226 MiB；需核对原始权重及转换产物许可，不能只凭框架许可发布。
- SenseVoice 只保留为非流式第二候选，不纳入首轮默认包；不默认叠加三套模型。
- Whisper 在新方案通过验收前继续作为默认与回退。不能静默转为云端识别。

## 可复现依赖准备

运行 `python3 tools/prepare-streaming-speech-runtime.py` 下载固定版本 AAR，**仅提取 Kotlin API classes.jar**。
运行 `python3 tools/prepare-streaming-speech-runtime.py --check` 仅检查本地文件，无网络请求。
运行 `python3 tools/test-streaming-speech-runtime.py` 测试完整性、缺失 ABI 和路径穿越拒绝。

通用 AAR 的原生库包含 espeak/TTS 组件，不能直接作为本项目的识别库打包。
`tools/build-streaming-speech-android.sh` 从固定 v1.12.11 源码构建，关闭 TTS、说话人分离、命令行等入口，启用 JNI；
复用现有手写引擎的 ONNX Runtime 1.22.0 动态库，避免把另一份 1.17 运行库静态带入 APK。
依赖包哈希固定；kaldifst 使用该 sherpa 版本要求的 1.7.13，旧版 1.7.11 缺少所需 Normalize 重载，不能混用。
`tools/package-streaming-speech.py` 校验三 ABI、16 KiB 页对齐、动态链接、JNI 接口、模型和第三方声明，拒绝 TTS 符号或额外资产。
模型和组件许可证放入 `assets/speech-streaming/licenses/`；其中构建脚本列出源代码下载地址和校验和。
下载在构建机器进行，不在用户手机录音时进行。正式接入必须把模型文件固定到不可变版本、逐个校验并附带所需许可证和第三方声明；不接受首次下载后自动信任计算出的哈希。

实验包仅额外打包约 200 MiB 的 Zipformer 模型，不打包 Paraformer；首次使用需复制到应用私有目录，会增加存储占用和准备时间。
其模型大于现有约 57 MiB Whisper；低内存设备应继续使用 Whisper。流式化不等于模型加载更快。

## 构建与使用

先按现有 Android 文档准备 JDK 17、SDK、NDK、Rust/Rime、手写与 Whisper 依赖，正常执行 `tools/verify-android-beta.sh`。
再运行：

```bash
bash tools/verify-android-streaming-beta.sh
```

该脚本构建三 ABI、准备模型与声明，执行 JVM 测试、Lint、APK 和测试 APK 编译，并检查实际 APK 内容。
输出位置仍为 `platform/android-ime/app/build/outputs/apk/debug/app-debug.apk`，版本名带 `.streaming-experimental`。
这是本地调试签名包，不会自动提交或更新 GitHub Release。

安装后到设置保留“内置离线语音”开启，再开启“实验性中英流式语音”，长按空格开始录音；等待准备完成再说话。
临时文字只显示在输入法内，可以修订；结束后沿用原有确认上屏设置。关闭开关恢复 Whisper。
流式模式暂不使用 Whisper 热词、独立 VAD 开关，不承诺自动标点。
录音最长 60 秒，过载明确报错，不静默丢音；空闲 120 秒或内存压力时释放模型。
非阻塞录音的小片段先聚合为 100 毫秒再入队，停止时保留尾部不足一块的音频；队列最多 64 块。

`ZhimoSpeechTiming` 日志只包含耗时和音频长度，不包含正文：`prepareMs` 包含私有目录安装/校验及模型加载；
`firstTextAfterPrepareMs` 是准备完成到解码器首次非空结果（不含准备、也不等于屏幕实际绘制时间）；
`tailMs` 是停止采音到最终解码完成，不含用户确认时间。没有结果时首字指标为 -1。

设备原生验证（必须使用实验 APK 和对应测试 APK）：

```bash
adb install -r platform/android-ime/app/build/outputs/apk/debug/app-debug.apk
adb install -r platform/android-ime/app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w -e class dev.zhimo.ime.StreamingSpeechTest \
  -e runStreamingSpeech true dev.zhimo.ime.test/androidx.test.runner.AndroidJUnitRunner
```

原生用例覆盖模型安装、重复流创建/释放和静音不产生文字；不能代替录音权限撤回、编辑器切换和真实口语质量验收。
另可运行 `python3 tools/prepare-speech-eval-fixtures.py`，把生成的 `target/speech-eval-fixtures/jfk.pcm`
推送到 `/sdcard/Android/data/dev.zhimo.ime/files/speech-test/jfk.pcm`，在上述命令中增加
`-e runStreamingSpeechFixture true`，验证公开样本在输入结束前出现临时结果及最终英文识别链路。

## 当前桌面小样本结果

两引擎采用固定模型、CPU 两线程、每条样本新进程，在构建机进行测试；编译同时运行，耗时不作正式性能排名。
报告位于 `target/streaming-speech/{zipformer,paraformer}-eval.json`，仅记录指标，不写识别正文。

| 指标 | Zipformer | Paraformer |
| --- | --- | --- |
| 两秒静音/两秒纯音误输出 | 均为 0 | 均为 0 |
| 11 秒英文 JFK 样本词错误数 | 1 / 22 | 7 / 22 |
| 该样本解码耗时（不含启动，CLI 四舍五入值） | 3.8 秒 | 4.3 秒 |
| 该样本整个进程耗时（含模型启动） | 14.68 秒 | 12.61 秒 |

这个结果只支持保留 Zipformer 作为下一步实验候选；不是全面准确率排名，也不是相对 Whisper 的加速倍数。
尤其不能把静音样本的 `language=zh` 当作中文语音验收：当前小样本没有人工核对的中文口语参考文本。

## 接入设计

1. 抽象语音会话：开始、喂入音频、临时结果、结束、最终结果、取消、释放。Whisper 与流式引擎使用同一上屏保护。
2. 录音与推理使用独立工作线程、有界音频队列。推理落后时显式报告资源不足，不能阻塞录音读取或静默丢音；禁止无界排队。
3. 模型在用户进入语音功能时后台准备，受内存压力控制释放；未进入语音功能不长期抢占输入法内存。
4. 临时结果只更新输入法自己的预览区，最多固定频率刷新。结束时补齐模型要求的尾部音频、排空解码，再确认一次最终结果；不能直接把临时结果写入聊天框。
5. 切换编辑器、进入密码框、权限撤回、关闭键盘、取消或服务销毁时，旧会话不再上屏；对象只由拥有它的工作线程释放。
   原生模型加载不能即时中断；取消会阻止后续录音和旧结果回调，工作线程待原生调用返回后清理。180 秒解码检查也不是强制杀线程的硬时限。
6. 一次任务只用一个引擎。初始化失败可在录音开始前提示回退；录音中失败不能悄悄重录或把已丢失的音频当完整输入。
7. 模型热词、标点、简繁转换和数字格式分别验收。不支持的能力需明确说明，不能强行套用 Whisper prompt 参数。

## 对照与上线门槛

用相同、明确授权的公开或用户同意的音频比较 Whisper、Zipformer、Paraformer；覆盖普通话、英文、中英混合、数字、姓名地名、轻声和噪声。

- 音频长度分 3、10、30 秒，测试冷启动、连续第二次和间隔 40 秒。
- 单列准备时间、模型加载、首字延迟、停止后等待、总推理耗时、实时率；流式与非流式的首字延迟口径不同，不混为一个加速倍数。
- 比较中文 CER、英文 WER、数字与专有名词准确率；不能用是否包含汉字作为质量达标条件。
- 比较峰值内存、三 ABI 包体积、连续使用发热与电量、麦克风竞争、后台取消及不同输入框切换。
- 默认仅记录不含正文的时间与资源指标，不持久化个人录音或识别内容。
- 只有目标手机上的速度明显改善、质量无不可接受退化，且生命周期与离线包校验通过后才更改默认引擎。桌面跑分不能替代手机结果。

实体手机的首字延迟、停止后等待、峰值内存、中英混合和中文 CER 仍是上线门槛。通过前不更换默认引擎。
