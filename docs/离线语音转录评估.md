# Zhimo 离线语音转录评估

最新实施进展见 [语音转录优化与验收](语音转录优化与验收.md)。本页旧问题列表为历史基线，不能据此判断当前 Android/iOS 代码。

> 以下保留为实施前的评估基线。后续 Android 内置模型、JNI 推理和录音接入已另行实现，最新状态与实测证据以 [内置离线语音交付](内置离线语音交付.md) 为准；其他平台及流式能力不能由此自动标记完成。

## 结论

已有可复用的语音接口和离线批处理适配器，但尚未形成「五个平台安装后，无需联网即可稳定中英文听写」的完整产品。尤其不要将手写模型随包内置，误认为语音模型也已随包内置。本轮对语音做代码审计和现有测试，不实施新的语音引擎、模型下载或系统权限变更。

## 主要问题与优先级

### P0：离线能力和隐私说明必须真实

1. **Android 缺少自主离线引擎链路。** 当前只把系统识别出的文字送给 NativeIme.speechResult，没有音频采集到本地 Whisper 的 JNI 绑定，也没有 ASR 模型资产。系统服务不可用时，独立 ASR 不能自动接管。
2. **iOS 不是严格离线策略。** 不支持端侧时没有拒绝启动或取得联网授权，存在走系统网络服务的可能。若产品声明严格离线，应在不满足条件时停止，并提示原因，而不是仅在支持时设置 requiresOnDeviceRecognition。[Apple API](https://developer.apple.com/documentation/speech/sfspeechrecognitionrequest/requiresondevicerecognition)
3. **离线偏好不等于强制离线。** Android 的 EXTRA_PREFER_OFFLINE 可能被具体识别服务忽略；当前专用 on-device 分支与允许网络的系统分支应在 UI 上明确区分。App 自身没有 INTERNET 权限也不能证明独立系统服务不会联网。[Android 文档](https://developer.android.com/reference/android/speech/RecognizerIntent#EXTRA_PREFER_OFFLINE)

### P1：实时性、取消和资源控制

- Whisper Provider 在 finish 前只积累样本；结束后启动进程，只产出 Final，没有真正的 Partial。interim_results 参数没有改变这一行为。
- finish 在调用线程写完整 WAV 并 sync_all，只有模型推理在线程中进行；不能将整个结束动作称为完全非阻塞。
- cancel 只删除内存会话，不终止已启动的推理进程；没有进程超时、取消回收或后台资源预算。
- 临时 WAV 的文件名由进程 ID 和会话编号构成，不是安全随机创建；同进程不同 Provider 使用同目录时可能冲突。权限依赖默认 umask，进程异常退出可能留下音频。建议使用专用私有目录、独占随机文件/内存输入，并验证取消和崩溃清理。
- 120 秒限制位于 SpeechController；CLI 直接调用 Provider，不经过该限制。CLI WAV 解析采用固定偏移和字节搜索，未完整验证 fmt/data 块、格式标签及边界，不适合作为通用导入器。
- EnergyVad 已有算法和单元测试，但未接入现有 Whisper 会话的自动端点流程；逐帧线性重采样缺少跨帧状态，持续音频还需质量验证。

### P1：语言和平台接入

- Android 没有明确设置 EXTRA_LANGUAGE，结果却使用系统 Locale 标记；输入法中英切换不等于语音语言切换。
- 只检测设备是否存在端侧识别服务，没有对当前语言模型的安装、下载、支持情况进行完整探测。可按 API 版本使用 checkRecognitionSupport 等接口；它从 API 33 提供，低版本需单独处理。[SpeechRecognizer 文档](https://developer.android.com/reference/android/speech/SpeechRecognizer)
- Manifest 未声明 RecognitionService 的 queries 可见性，需按系统版本和服务路径补齐兼容性验证。权限拒绝、服务缺失、语言包缺失、断网、忙碌和超时目前主要以通用错误反馈。
- iOS 自定义键盘不能直接使用麦克风；应由容器采音，并设计明确的预览、返回和提交流程，不能假设能复制 Android 键盘的录音方式。[Apple 自定义键盘限制](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/CustomKeyboard.html)

## 建议的通用底座方案

保留 SpeechProvider / SpeechController，但把「能力已编译」「模型已安装」「当前语言可离线」「正在运行」分开暴露。录音、重采样、VAD、推理、文本规范化和输入会话校验分层，使用有界音频队列与可取消任务。

1. **第一阶段：Android 自主离线闭环。** 建立本地库级推理绑定和 AudioRecord 音频流，私有线程处理重采样与 VAD，后台加载固定版本模型；禁止静默网络回退。whisper.cpp 提供 Android 和 Apple 集成示例，可作为工程接入参考，但示例存在不代表本项目已集成。[官方仓库](https://github.com/ggml-org/whisper.cpp)
2. **第二阶段：输入法实时体验。** 流式中间结果只作为预编辑文本，最终结果确认后提交；用请求 ID、编辑器 ID 与版本过滤迟到结果。明确区分“结束识别”和“取消”，提供语言、模型和离线状态。
3. **第三阶段：统一分发与跨端。** 模型描述包含语言、许可证、来源、哈希、运行时版本、内存需求和设备能力要求；支持随包版与可选离线模型包版。用相同测试集比较模型后再确定默认权重，不以体积或宣传参数推断中文效果。

模型可以随安装包分发，但系统厂商的语音语言包不能直接当作本项目资产复制。应为有明确再分发授权的独立模型实现完整性校验、版本兼容、原子安装和失败回滚。不能把当前手写模型的体积或授权套用到语音模型。

## 验收建议与本轮限制

以下是待执行的验收设计，不是已测指标：

- 首次安装后断网启动；缺少系统语音服务的手机也能用自主模型识别。
- 普通话、英文、中英混说、数字/日期/专有名词、静音、噪声和不同说话人分组测试，分别记录中文 CER、英文 WER，不混为一个准确率。
- 按低/中/高档 ARM 真机记录模型加载时间、首个中间结果延迟、结束到最终结果的 p50/p95、RTF、峰值内存、温升和包体；本轮不提供未经测量的数值。
- 取消、切换输入框、锁屏、权限撤销、来电、后台回收后无错投文字、无残留录音、无持续后台推理；联网行为与音频落盘分别验证。

本轮执行 `cargo test -p ime-speech -p ime-ffi`：19 项通过，2 项依赖真实 Whisper 的测试被忽略。通过项覆盖通用控制器、音频处理和 ABI 等逻辑，不代表已验证中文或英文实际识别准确率。

本轮未下载新 ASR 权重、未录制或上传用户语音、未调用外部语音服务。现有真实 Whisper 测试依赖外部可执行文件、模型和音频组合，不能用普通单元测试通过代替真实离线转录验收。手写安装包和测试记录见 [数字字母与混合手写](数字字母与混合手写.md)。
