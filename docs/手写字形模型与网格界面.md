最新版本将字形识别默认开启，并将停顿叠写替换为 [三格横向连写](三格横向连写.md)。本文默认关闭与安装包为历史记录，质量门槛仍适用。

后续按键与手写布局及更新的 APK 见 [参考键盘布局改版](参考键盘布局改版.md)。本文模型说明仍适用，下方 APK 和验收是本轮历史记录。

日期：2026-09-13。本轮交付为 Android 实验性离线字形识别和候选界面改版，不是已完成独立多人准确率验收的正式模型升级。

## 使用方式

安装本轮 APK 后，打开 Shurufa 设置，开启 **“实验性离线字形识别（重新打开手写生效）”**，再退出并重新进入手写模式。

开启成功后画板标签显示“字形·实验”，关闭时显示“中文单字”，便于识别当前引擎。

模型已在 APK 内，无需联网或额外下载。开关默认关闭；关闭并重新进入手写可返回原轨迹引擎。开关不是准确率承诺，主要用于验证截图中“制、清、存”这类原轨迹引擎失败的写法。

## 界面完成项

- 首行展示前五候选，末尾为“更多”，不再用巨大上一页/下一页挤占候选。
- 更多候选覆盖画板显示为上下滚动网格，保留最多 100 候选；点击“收起”恢复原笔迹，不清空正在写的字。
- 次要按钮使用应用自身颜色、尺寸、圆角和按压反馈，移除系统按钮阴影与默认最小宽度影响。
- 常驻“重载模型”移除；仅模型准备失败时，状态区提供点按重试。
- 撤一笔、清空保持固定位置；增加放大/缩小画板。已有笔迹时拒绝调整大小，提示先选字或清空，避免已有坐标被错误解释。
- 区分正在准备、书写中、识别中和候选提示。写新笔时不提交旧结果，候选提交后旧按钮失效。
- 网格行高考虑系统字号和输入法字号。此处不宣称所有厂商主题、横屏、TalkBack 和特大字号组合均已真机验收。

## 新识别链路

笔迹 → 整字居中、等比例绘制 → 512 方形黑字白底 → 48 × 48 图像置于 1 × 3 × 48 × 320 张量 → ONNX Runtime CPU → 单字符 CTC 路径概率求和 → 候选 → 用户确认上屏。

`ImageHandwritingProvider` 使用单后台线程、两条内部计算线程；初始化与推理不在 UI 线程，关闭后释放模型 Session，旧回调不再触达已关闭面板。只使用画板笔迹，不读聊天内容，不保存笔迹，不增加网络权限。

使用 PP-OCRv5_mobile_rec 的 RapidAI ONNX 转换版本，模型为 16,631,306 字节，固定 SHA-256：

`5825fc7ebf84ae7a412be049820b4d86d77620f204a041697b0494669b1742c5`

字符表从已校验 ONNX 元数据读取；不猜测字符表，不将不同引擎的原始分数相加。输入仍限制单字；输出并不表示完整的连续文本、多语言或重叠手写产品能力。

中文模式只保留 Unicode Han 候选，排除横线等符号抢占“一”的候选位置。512 → 48 使用区域平均缩小，避免稀疏双线性采样漏掉细笔画。Android 新增“细横线不能消失”断言，不能仅靠两个空白渲染结果相等通过变换测试。前 100 候选使用有界优先队列，减少全字表排序的分配开销。

原始权重卡标注 Apache-2.0，转换分发来自 RapidAI，ONNX Runtime 1.22.0 为 MIT；原模型卡、许可证和 Runtime 第三方声明均随包附带。完整来源见 [模型资源清单](../models/handwriting-image/README.md)。这些许可不替代原 Zinnia/Tegaki 资源许可。

## 三张截图的本机结果

只裁取用户提供截图中的笔迹区域，并去除浅色背景/定位线；没有上传截图、没有把截图或衍生笔迹打进 APK/版本库。目标字暂为人工判读，尚未得到用户明确确认。

| 开发样例 | 贪心输出 | 单字前五候选 | 本机推理时间（单次观测） |
|---|---|---|---|
| 01，暂按“制” | 制 | 制、製、刷、俐、刺 | 29.66 ms |
| 02，暂按“清” | 清 | 清、洁、法、涛、请 | 32.87 ms |
| 03，暂按“存” | 存 | 存、有、在、古、李 | 38.32 ms |

CPU 冷加载单次观测 118.43 ms；进程峰值 RSS 143,508 KiB（包括 Python/运行库，不是模型单独内存）。桌面 ONNX Runtime 为 1.30.0，Android 为 1.22.0，必须分别验证，不能拿桌面耗时当手机耗时。

以上仅是同一用户三个截图的开发实验，**不是“准确率 100%”**。截图没有笔顺，不伪造轨迹与旧引擎作等价对比。PNG/JPEG 笔迹提取与手机从触摸点渲染也不是同一条预处理路径，二者分别验证。

## 评测工具

`tools/evaluate-handwriting-image.py` 本地读取模型和案例 JSON，输出冷加载、推理、前五候选、目标字排名和进程内存。只统计确认过标签的独立 test 样例，开发样例不会混入正式指标。

- 拒绝重复样例 ID、同一书写者跨训练/开发/验收集合、未确认的 test 标签。
- `tools/test-handwriting-image-eval.py` 验证 CTC 概率与穷举路径一致，以及集合隔离检查。
- 只有显式传入 `--export-tensors` 才导出本地设备测试张量；张量包含笔迹信息，应按私有测试数据处理，不提交或随包分发。
- 当前本地案例清单位于被忽略的 `target/handwriting-image-cases.json`；原始截图仍留在用户 Downloads，未改动。

```bash
python3 -m venv target/handwriting-ocr-venv
target/handwriting-ocr-venv/bin/pip install onnxruntime==1.30.0 pillow==12.3.0 numpy==2.5.3
target/handwriting-ocr-venv/bin/python tools/test-handwriting-image-eval.py
target/handwriting-ocr-venv/bin/python tools/evaluate-handwriting-image.py \
  models/handwriting-image/pp-ocrv5-mobile-rec.onnx target/handwriting-image-cases.json
```

## 仍未完成的发布门槛

1. 用户确认目标字并验证实际触摸书写，而不仅是静态截图。
2. 多书写者独立测试集：Top1/5/20、完全漏字率，按连笔、笔顺、偏写、小字分组。
3. 真实 ARM 手机冷启动、长时间内存、低端机 P95 延迟、耗电和无障碍验收。
4. 模型通过上述门槛后，再决定默认启用、轨迹/字形候选融合和本地个性化重排；本轮未实现融合或个人字形训练，避免用三例调参造成虚假提升。

实验性字形 Provider 目前仅在 Android 接入；Windows/Linux/macOS/iOS 尚未接入该 ONNX 链路。连续和重叠书写仍未实现。原归一化修复、历史 APK 和已知笔顺问题见 [上轮记录](手写识别质量整改.md)。

- 公共 `tools/verify.sh`：69 项通过，2 项外部 whisper 测试忽略；格式、严格 Clippy、C ABI、TSF 核心探针通过。
- Python 评测工具 2 项测试通过。
- Android `assembleDebug`、`assembleDebugAndroidTest`、`lintDebug` 均通过。Lint 0 错误、4 警告（两个工具版本更新提示、两个程序化 View 工具构造函数提示）；模型构建/运行校验均通过。三 ABI 包含原生 Rime、JNI 和 ONNX Runtime，签名及 ELF 依赖校验通过。只声明 RECORD_AUDIO，无 INTERNET 权限，APK 不含用户截图或 `.f32` 测试张量。
- API 35 x86_64 专用模拟器在 `Active default network: none` 下更新安装：14 项基础/面板/键盘测试、2 项原轨迹模型测试、1 次原轨迹真实画笔＋网格上屏、2 项字形模型/渲染测试、1 次字形真实画笔＋网格上屏、1 项本地截图张量设备测试均通过，无跳过。键盘测试有重复执行，不将执行次数冒充独立方法数。
- 字形渲染测试检查细横线存在、平移/缩放/画布尺寸/笔顺变化一致性；候选过滤测试排除“—”抢占中文“一”。曾出现的细横线测试失败已修复并重跑通过，没有删除失败用例。
