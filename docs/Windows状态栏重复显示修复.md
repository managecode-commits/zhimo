# Windows 浮动状态栏重复显示修复

Copyright © 2026 立方田 <managecode@gmail.com>

用户截图中出现多条 `Z 中 手 麦 ⋯`。旧实现由各 TSF 实例创建独立窗口，只有进程级前台判断，缺少独占显示协议和线程 UI 焦点监听。

## 修复

- 接入 ITfThreadFocusSink，在失去线程 UI 焦点时隐藏浮动栏；保留原有键盘焦点判断。
- 显示前同时核对前台进程和线程，不让同进程后台线程创建可见栏。
- 新版使用会话内命名互斥锁：先隐藏旧栏再释放，随后新实例才可显示。获取使用零等待，不阻塞其他应用。
- 同线程实例额外防递归获取，避免 Windows 互斥锁的递归语义绕过独占限制。
- 150 毫秒轻量检查兜底隐藏非前台栏、响应全局隐藏设置；锁持有者退出后使用 abandoned mutex 恢复。
- 隐藏／关闭时释放鼠标捕获和锁；点击时重新核对前台线程，避免旧栏操作错误输入目标。
- 横竖布局、拖动位置和显示设置保留；原生任务栏模式图标保留恢复入口。

## 验证边界

修复包：`target/packages/zhimo-windows-statusbar-fix-20260915.zip`，包含 x64/x86 TSF、最新单字手写画板及离线模型。解压后执行管理员 64 位 PowerShell `./install.cmd -Upgrade`，再注销登录。旧包不覆盖。

两种架构交叉编译通过，安装 PowerShell 脚本的语法与注册路由模拟测试通过。当前环境无 Windows 宿主，下面新增的 Win32 互斥测试已编译入探针，尚未在本机执行；安装时会执行。不可把这些检查表述为多应用实机重复窗口问题已经验收。

探针新增同线程竞争、其他线程竞争、释放移交及持锁线程退出后的恢复测试，由 Windows 安装脚本在注册前运行 x64/x86 探针。交叉编译不等于 Windows 上的视觉验收。

锁被卡死宿主持有时，新浮动栏宁可暂不显示；原生输入模式图标仍可用。旧版 DLL 不参与此协议，升级后需保存文档、注销 Windows 再登录，不能只关闭安装窗口。不要为清理状态栏强制结束用户编辑器。

实机需检查：记事本／EmEditor 32 位／浏览器间切换、同进程多个窗口、显示桌面、切换其他输入法、横竖布局、拖动、隐藏恢复。正常应只显示当前 Zhimo 输入目标的一条浮动栏。
