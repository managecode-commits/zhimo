# 桌面实体键盘字符与拼音输入

本文记录 Windows TSF、Linux IBus/Fcitx5 的实体键盘输入；2026-09-21 大小写修复同步修改 macOS InputMethodKit 源码。不包含桌面可点击虚拟键盘。

| 操作 | 行为 |
|---|---|
| Shift+Space | 切换中文拼音 / 英文；切换时取消未确认的组合 |
| 英文模式 | 字母大小写、数字、标点、小键盘由应用原生处理，不自动替换成联想词 |
| 中文模式小写字母 | Caps Lock 关闭且未按 Shift 时累积拼音；英文单引号作为拼音分隔符 |
| Caps Lock | 临时英文直输，由系统决定字符大小写；关闭后恢复原先选择的中英文模式 |
| Shift＋字母 | 临时交给系统输入大写；Caps Lock＋Shift 的小写也由系统处理 |
| 1～9、空格 | 有候选时选词；无组合时正常输入数字和空格 |
| Enter / 小键盘 Enter | 有拼音时上屏原始拼音，如 `jixu`，不选择汉字、不附加换行；无组合时交给应用正常处理 |
| 方向键、翻页 | 按各框架已有候选导航处理；IBus/Fcitx5 空格确认当前高亮候选 |
| 标点 | 有组合时先确认候选，再将原始标点交给应用；不强制转换为中文全角标点 |
| Backspace / Esc | 编辑拼音 / 取消组合；无组合时交给应用 |
| Ctrl / Alt / Super(Win) 快捷键 | 保留给应用和系统，不误切换模式 |

Windows 保留参考拼音引擎；Linux 安装包默认使用 Rime。Windows 尚未接入完整 Rime，
不能据此声称跨平台词库与排序完全一致。

## 2026-09-21 大小写修复

- 不再在中文模式下把 Caps Lock／Shift 产生的大写字母强制喂入拼音引擎。
- 大写临时直输不修改基础中英文选择。Caps Lock 开启时点击中英切换或按 Shift+Space 改变的是基础模式，关闭锁定后才恢复该模式；这不是一个模拟系统 Caps Lock 的按钮。
- 已有拼音时按 Caps Lock，或输入 Shift＋字母，先按原拼音提交（例如 `nihao`），再把原始按键交给宿主。不会自动选“你好”，也不会把新的大写字母追加到旧拼音。原拼音提交沿用 Enter 路径，不学习为用户选词。
- IBus 同时修复字符串格式 `CloseComposition` 未处理的问题；大写直输前明确收起旧拼音和候选。
- Windows 原生语言栏与悬浮栏在锁定时显示 `A`，关闭后显示原来的“中／英”；语言栏提示明确这是大写锁定。
- Linux IBus/Fcitx5 的模式标签显示 `A`。使用事件中的锁定掩码，不从字符大小写反推 Caps Lock；Caps Lock 按下时不猜测前/后状态，在释放或后续事件同步。跨上下文的状态在收到该上下文的键事件时校准，尚未承诺所有桌面面板瞬时刷新。
- macOS 监听 `flagsChanged`，菜单显示大写锁定说明，保留基础语言选择。源码已修改，当前 Linux 环境没有 macOS SDK，不能声称 Swift/IMK 编译或宿主验证通过。
- Ctrl/Alt/Win(Command/Option) 快捷键、密码框与系统键盘布局仍走原有保护/透传路径；不合成英文键值，不修改键盘灯。

验证：Windows x86/x64 交叉编译通过，包含大小写策略静态断言和新增语言栏大写恢复探针；探针还需在 Windows 执行。Ubuntu 24.04 与 Debian 12 的 Fcitx5 编译通过，IBus 实际路由及消息处理方法的 7 项隔离测试在两者均通过（替身编辑器和运行时，不是 GUI 自动化）。macOS 的 3 项打包契约检查通过，不等于大小写功能实测。

测试入口：`python3 tools/test-desktop-case.py`（需 IBus GI）；日志见 `target/desktop-caps-{windows64,windows32,ubuntu-final,debian-final}.log`。

原有 `platform/linux-ibus/test_keyboard.py` 的 13 项回归在 Ubuntu/Debian 也均通过，只为测试替身补充新的状态字段，未放宽原有断言。每个发行版共通过 20 项 IBus 隔离测试；最终测试日志为 `target/desktop-caps-{ubuntu,debian}-{tests,keyboard}.log`。

本轮未生成新的安装包；以下历史安装包不包含此修复。后续须重新打包安装并重启加载 DLL/插件的进程，再验收 Caps Lock 开关、Shift 临时大写、Caps Lock＋Shift、已有拼音与焦点切换。Windows/EmEditor、macOS 和 Linux X11/Wayland 的真实宿主验收尚未完成。

## 修复点

- 2026-09-15：参考拼音引擎拆分 Enter 与 Space；`jixu + Enter` 输出 `jixu`，`jixu + Space` 输出 `继续`。原始拼音提交不作为选词学习，并清除本次分词／组词状态。已选字若已上屏，不撤销它，回车只提交剩余拼音。
- 回车回归覆盖参考引擎、C ABI、IBus 主回车／小键盘回车与空闲透传；Ubuntu 容器中用实际 Rime 和随包词典验证回车输出拼音、空格输出汉字。Windows/macOS 宿主实机未验收；此代码修改尚未重新打包，旧安装包不会自动变化。
- IBus 的 keyval_to_unicode 在 GI 中可返回字符串，不能总是调用 chr()；旧代码会在处理字母时抛异常。
- 英文模式直接透传，避免英文数字标点与未确认联想组合交错。
- IBus 翻页后数字选词使用当前页偏移，空格使用当前高亮候选，提交后清空旧候选缓存。
- Windows 不把 Shift+引号强制当作拼音分隔符，Shift+数字不当数字选词，Win 快捷键不被字母拦截。
- Windows 在同步编辑会话结束拼音后将原始标点交回宿主；其键事件处理状态遵循
  [Microsoft OnKeyDown 接口定义](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfkeyeventsink-onkeydown)。
  不自行转换键盘布局字符，但真实宿主中的事件顺序仍需 Windows 实机验收。

## 可见状态与鼠标切换

| 平台 | 状态与入口 |
|---|---|
| Windows TSF | 系统任务栏输入指示器：“中”／“英”；点击切换。使用 GUID_LBI_INPUTMODE 原生按钮，不再使用悬浮窗 |
| Linux IBus | 发布标准 InputMode 属性，符号“中”／“英”；在输入法面板或输入源菜单中点击“中文拼音”／“英文直输”切换 |
| Linux Fcitx5 | 状态区注册“中”／“英”动作，并同步当前输入上下文的子模式标签；在面板或菜单点击切换 |

三端均与 Shift+Space 同步；切换取消尚未确认的拼音，不提交为英文字母。
Linux 入口的位置与是否直接展示文字由桌面面板、主题及扩展决定，不保证所有桌面都常驻显示。
密码域不允许通过此入口启动拼音。Windows 模式按钮由系统输入指示器管理，
延迟执行的鼠标切换会校验上下文与事件代次，避免影响已经切换的编辑区域。

Windows 鼠标操作使用 [TSF 编辑会话](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfcontext-requesteditsession)
允许的同步或异步调度，而非在鼠标回调中强制同步编辑。
上述 UI 已实现并编译，但尚未完成真实 Windows、GNOME 或 Fcitx5 桌面的鼠标交互验收。
升级后请注销并重新登录，防止进程继续加载旧 DLL 或插件。

### Windows 原生任务栏修正

用户参考图中的“中／英”属于系统输入指示器，旧悬浮按钮实现不符合要求。
新版实现 ITfLangBarItemButton + ITfSource，成功切换后通知图标、文字、提示更新；
启用时 AddItem、停用时 RemoveItem 并断开点击回调。MinGW 也注册系统托盘支持类别，
不再只在 MSVC 构建中注册。品牌图标保留 Zhimo Z，模式图标使用主题可着色的单色中／英。
依据 [微软 IME 系统托盘要求](https://learn.microsoft.com/en-us/windows/apps/develop/input/input-method-editor-requirements)
及 [语言栏项标识规定](https://learn.microsoft.com/en-us/windows/win32/api/ctfutb/ns-ctfutb-tf_langbariteminfo)。

新增 Windows probe 检查 COM 接口、状态通知、中英文字与图标、左右点击差异及解除回调；
仅完成编译，随安装脚本在目标 Windows 运行。仍需实机确认 Explorer 显示、焦点保持及缩放。
